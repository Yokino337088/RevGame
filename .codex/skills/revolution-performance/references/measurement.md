# 测量与归因

计时阶段与取证阶段分开；测不到不等于0。先核对真实工程与报告，跨设备/内容/攻击数/冷暖状态不算可归因收益。

## 固定工作量

记录CPU/GPU/平台、代码/资源/Unity版本、渲染管线/API、Game实际分辨率/画质、同步设置、场景/种子/成员/攻击数、模型步长、反馈预算、预热、每段实际时长/重复数和帧预算。吞吐与屏幕刷新分开：60Hz屏幕不能呈现每秒90张独立刷新。

| 模式 | 可以证明 | 不能替代 |
|---|---|---|
| .NET固定操作 | 规则/顺序、局部CPU/有效分配 | Unity生命周期、GPU/AB/设备FPS |
| 冻结规则固定画面 | 同Renderer/纹理/画质的批次/像素成本 | 持续AI/攻击/GC峰值 |
| 真实持续固定输入 | 规则/攻击/反馈/资源成本与帧分布 | 正常难度/其它Boss技能覆盖 |
| 密集反馈 | 实际峰值、调度公平/避让/清理 | 全场CPU或目标FPS |
| 冷AB/多次进出 | 白图/就绪/释放/增长/加载尖峰 | 纯算法稳态速度 |

复用已有受控夹具，不静默改生产属性。RevGame案例双方24棋、种子1025+章、补血维持负载、2.5秒预热和20/35/16预算只是其压力输入，不推广为其它项目数值。

## 降低观察者开销

- 稳定窗口仅写预分配值类型数组；超容量失败，不截断。窗口外排序/CSV/JSON/场景枚举/截图/GIF。作业缓冲内存不是生产常驻缓存。
- 用当前Unity支持的ProfilerMarker/ProfilerRecorder/FrameTiming；GPU只收新时间戳且正有效帧时，缺样标缺失，不用CPU提交代替。
- 已知分配探针验证计数有效；RevGame Mono曾一直返回0，不能拿它报零GC。Editor整帧分配含字体/工具/业务，不能全归棋子。
- 保留异常检测，普通日志过滤对照注明并finally恢复；不关屏幕文案。不高频MCP/系统查询制造离群帧。
- 操作基准多轮中位、排除JIT/预热；整场保存每轮/每章，不取最好样本。实际完成时长、十分钟/十次重入不能用计划或旧文件代替。

## 判断瓶颈

80FPS=12.5ms，90≈11.11ms，60≈16.67ms。FPS=帧数/墙钟秒；P95/P99是排序后帧间隔位置，保留max与超预算比例。平均快不能覆盖偶发慢帧。

| 证据 | 路径 |
|---|---|
| 规则/目标/候选独立CPU段贵 | 索引/缓存/快照/容器/排序，保持提交顺序 |
| CPU提交/UGUI贵 | 脏写、纹理/材质/Mask/排序；合批分别A/B |
| GPU片元贵 | 同画面诊断背景/采样/覆盖，恢复内容后优化数学 |
| GC分配/停顿 | 有效计数和必要栈、闭包/文本/池热冷；分配≠停顿 |
| 内存增长 | 相同根集完整依赖、租约/池/字体/章节寿命 |
| 墙钟忽快忽慢但线程/GPU不对应 | 电源/温度/频率/Editor呈现/后台调度未知保留；同状态A/B |

父Profiler含子调用不可相加，线程/GPU并行与等待不可累加。Timer包含业务回调不等于内核慢；EditorLoop不全是游戏，不从整帧扣它算“纯游戏FPS”。Frame Debugger停帧事件表不是持续批次基线。

诊断停绘/HUD关闭必须恢复。沼泽GPU11.50→停绘3.65ms仅定位背景贵，**不能宣称已优化68%**。

## 唯一作业与完整清理

请求→runId→设备/参数→实际段完整→错误/取消→正式回首页→逻辑/租约核对→恢复设置。EnterBattle=true只是accepted，需IsTransitioning=false、Screen和可画资源；冷AB不能预加载全图集掩盖白图。

RevGame先发现真实 `game.perf.begin/state/cancel`、反馈begin/state。结果runId匹配，completed/cleaned=true/cancelled=false/errors=0，段数=(last-first+1)*repeats，seconds≥请求，人数/攻击满足夹具门禁。脚本检查完整性不证明两次温度/调度/画质/代码状态可比，只输出观测差异。
