# 逻辑帧与表现帧

固定逻辑步给模拟统一的时间增量。渲染按设备能提供的帧率消费显示样本。先读真实逻辑入口、视图回调、事件消费顺序和自动化能力，再确定耗时来自模拟次数、每步计算、表现重建、提交还是 GPU 绘制。按业务需要保留项目现有步长和网络协议。

## 设计提交与显示边界

1. **权威状态归规则。** 在现有业务入口完成移动、索敌、伤害、占格、随机和结算后发布采样。给显示数据带上局次或世界、逻辑时间、实体身份及复用代次。移动所需的数据可用有限容量的数组复用。视图在主线程消费，跨线程时约定发布、读完和复用缓冲的顺序。
2. **显示归表现层。** 渲染帧用本地显示时钟在已确认的坐标之间插值。同一实体的模型、血条、出生视图和相关挂点共用显示位置。段内比例限制在 0 到 1。下一样本晚到时停在已确认位置，连续更新时从当下显示的坐标衔接。常规插值通常会引入约一个逻辑步的显示延迟，验收时同时检查响应和运动连续性。
3. **断点明确。** 初次出现、瞬移或需要当步对齐的击退、槽位复用、暂停、重连或读档都要按语义对齐新样本或重置插值。退出域时清掉显示来源、绘制范围和仍持有的对象。回池复用容量，清除本局引用和迟到回调。
4. **离散事件单独消费。** 死亡、受击、命中、技能阶段和结算沿原事件路径、排序和预算。即使显示位置可以只采最新样本，也要确保必要的事件和生命周期回执按契约交付。命中判定、落子或网络权威输入始终读取逻辑状态。

## 让渲染帧只做需要的工作

- 把身份、血量、颜色与纹理坐标放在新样本或绘制归属变化时更新。在同一逻辑时间收到掉血时，刷新外观并保留当前位移段的起点和时钟。
- 用活动实体而不是容器容量决定实际顶点和索引范围。保留透明绘制顺序。出生特效接管时让批次跳过同一身份。普通表现帧只处理正在活动的特效租约，避免逐帧扫描所有空槽。
- 位置与较少变化的属性可用不同顶点流。先测 uGUI 重建、渲染提交或顶点上传是否占主耗时，再决定是否拆流。检查每次 API 调用开销、缓冲驻留和低刷时外观变化比例。静止且样本与批次都有效时可复用上一帧。
- 动作、切场、图集重绑、池归还和回调失效沿原入口。插值频率与技能逻辑、Sprite 逐帧动画和音效的时间域分别确认。

## RevGame 的三个用法

| 场景 | 先读的边界 | 选择 |
| --- | --- | --- |
| 远征 | `BattleLogic` 固定步驱动规则，`PieceView.MoveTo` 平滑落格后的显示。 | 按攻击、预测、反馈、提交分别定位，保持占格与打击节奏。 |
| 无尽 | `EndlessLogic` 使用表配置固定步。敌潮组件区分空间变化版本和显示变化版本。 | `EndlessHordePresentation` 只采样变化，`EndlessQuadBatch` 普通渲染帧只传位置流，外观更新时再传颜色和 UV。 |
| 决斗 | C++ 内核结算权威状态，C# 消费确认帧及显示缓冲。 | `PvpDuelView` 从 `DuelDisplay` 采确认帧，按既有帧确认与回放语义更新视图。 |

代码和复测来源见 [RevGame 实践](revgame-practice.md)。100 ms 是该无尽规则表的间隔。固定逻辑步和表现插值适用于现有单机和联网架构，内核、联机和线程重构各自按协议、预算和实测收益立项。

## 验收

- 同固定输入、种子与逻辑时间核对身份、索敌、命中、伤害、随机状态和结果。玩法同一时刻的读数要可对照。单独验证朝向、补间、血条、出生/死亡、跳位、暂停/恢复和重入。
- 对真实绘制位置测有位移帧比例和单帧位移。单个静帧适合看贴图、顺序和重影。量化持续流畅性需实际连拍或逐帧姿态证据，画面采集放在性能窗口外。
- 分别给出整帧、模拟步、表现提交和有效 GPU 帧时。提交量按每帧、每秒及相同可见方块归一化，注明哪个数据是实测、哪个按原布局估算。帧率提高时每秒提交量仍可能上升。
- RevGame 先发现 `endless.enter`、`endless.stress`、`endless.state`、`endless.horde-presentation-check` 等实际注册入口，等隔离场景就绪，最后用 `endless.home` 回大厅并核对收尾。短窗口 Editor 数据按本机口径描述，目标设备结论由实际 Player 或真机同条件复测给出。
