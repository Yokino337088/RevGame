# Android 运行时与宽屏验收

遇到 Android 包能构建但 UI 被裁、Shader 不可用、动画首帧为空、换章卡住或凭据写入失败时按本页分诊。构建环境、签名和验包见 [Android 构建与验包](../../revolution-unity-editor/references/android-build-and-verification.md)。

## 画幅、布局和触屏

- 把 1920×1080 当作设计坐标。窗口和相机按设备实际画幅工作，背景等比 cover 铺满。棋盘格、人物和 UI 保持比例，避免把整个窗口压成 16:9 或横向拉伸。若设备仍有黑边，分别读回实际窗口、合并后的启动 Activity、宽高比限制与 resizeable 元数据，再检查 Unity 相机 viewport。清除构建副本里已经移除的旧原生 Activity 和 manifest 覆盖。
- 把 UI 划成全屏视觉、普通安全区内容、棋盘侧栏与场景独立 HUD。遮罩、剧情背景及点击拦截层占全屏；正文、按钮和跳过入口位于安全区。棋盘 HUD 以同一套棋盘屏幕投影和 SafeArea 为输入，保留棋盘设计比例，把两侧交互控件扩展到可用空间，再对最窄安全画幅做约束。独立 HUD 单独验证屏幕角落的按钮与血条，别假设它会继承 RevUI 面板适配。
- 由预制体锚点、CanvasScaler 和原始偏移映射出新布局，在画幅、安全区或相机几何变化时重算。重复重排从原始坐标开始。UI 动画和页面重入后重验边界，读取实际点击命中对象及业务结果。
- Device Simulator 使用 UnityEngine.Device 的屏幕和设备视图。平台存储、原生插件及图形能力取实际运行平台。基线对照普通 16:9 Game 与宽屏有缺口设备，验安全区、棋盘与按钮交叠、长对白、实际点按；真机再验系统栏、横屏方向、触点与相机。见 [Unity Screen.safeArea](https://docs.unity3d.com/2022.3/Documentation/ScriptReference/Screen-safeArea.html)。

## AB、动画首帧与异步场景

- 分开记录编辑器直读、目标 AB 在编辑器加载、独立 Player、Android 真机。目标切换决定打包与条件编译，Windows Editor 的图形 API 仍由宿主决定。Android AB 的 shader.isSupported 为 false 只证明本次宿主组合失败；真机用实际图形 API、Player 日志和同版 Android AB 区分 Shader 变体与资源缺失。
- 出现「加载成功但没有可画 Sprite」时检查图集请求、首帧引用、控制器/状态绑定和真实 Renderer。控制器安装后可重绑并采样首帧，再验证 Sprite、动画实际推进及回池。资源按寿命通过 RevResManager 租用，先解绑引用再释放。用冷加载发现首开问题，避免预热所有图集。
- 角色互动分别断言触发、配置、表情图集、显示条件和排序。台词缺失时先断言业务和资源，再查冲突区域、隐藏规则和排序。头像与对白可分别排序，让对白在棋子前且安全区内，按项目需求验可见高度和文字空间。
- 同一回合事件可能同时更新场景资源和打开剧情。缓存命中时 OpenAsync 可以同步完成，旧章的布尔 Ready 可能误放行。持有流程锁，待事件发完及目标背景交付，核对章号、有效画面和请求代次，再开对应剧情。失败由一个入口回退，迟到加载只能清理。验证真实「Boss → 结算 → 领奖 → 下一章剧情 → 可落子」。
- 调清晰度记录原图、实际 Sprite 切片、导入上限、压缩和分包字节。避免源图与图集重复有损压缩，保留透明与切片。按资源生命周期分包，验证映射、依赖、载入和重入。包体与 GPU 解码占用分别测。文案和表更新先导表，再生成并核验字体子集；跨平台构建期间输入变化则按同一版本重建。

## 凭据和诊断

- 平台存储由服务按实际运行环境选择。Windows DPAPI 等桌面专用 API 无法直接用于 Android。用隔离槽或假凭据在真机验保存、重启读取、清除、写入失败和损坏配置。真实 Key 和签名口令不得写入日志或提交。项目明确选择的明文回退只适用于其数据目录与场景，应标明明文属性。
- Unity 原生崩溃保留 Editor.log 和崩溃记录。最后一个业务堆栈只表示当时正在做什么。重连、等编译、重新发现能力后按原输入复测。成功复测与根因定论分开记录。
- HTTP 自动化失败先确认传输、动作错误、心跳及域重载。动作仍写旧工单目录标记时记录真实契约缺口，可用项目受控动作切目标并读回状态。隔离 Play 由 RevMCP 发现并执行带断言及清理的计划，保留真实结果。
