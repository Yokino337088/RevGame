# 参考RevGame的AI自动化开发工作流

## 每次业务任务的最小闭环

**需求 → 真实工程示例 → 契约与最小设计 → 代码/配置/资产 → 编译与发现 → 规则/真实操作/AB视觉 → 收尾与证据。**

### 1. 输入与参考

读取目标项目AGENTS、用户最新约束和实际配置。按 [工程实践索引](revgame-engineering.md) 选择RevGame同类文件，阅读接口、关键方法、生命周期以及对应检查。记录固定提交或当前SHA，不能把旧策划的11回合、旧强化倍率、旧测试通过率自动带入目标工程。

若用户在长任务中修改需求，把新要求合入当前契约，标记哪些已跑结果只属于旧版本。数字变化需要重新验证对应算法与配置；只改README/Skills不能冒称又跑了游戏。

### 2. 编码前写清所有权与断言

| 项目 | 必须明确 |
|---|---|
| 生命周期 | 实例由谁创建/驱动/Dispose；场景、回合、短效owner如何分别回收 |
| 唯一写入口 | 服务/Logic如何提交，UI、GM、AI共用哪些原子动作 |
| 配置源 | 策划数值进Excel；纯表现材质参数与剧情SO依需求决定，不混入血攻算法 |
| 无副作用查询 | 判断合法性/预测伤害不扣牌、不改盾、不抽随机、不写占格 |
| 正反例 | 合法成功的后置差值；非法参数/冷却/无目标/耗尽/退出的拒绝与状态保持 |
| 表现验收 | 实际Prefabs/纹理/材质/动画/声音/遮挡，可见与播放的证据 |

例如助手增长：实际命中后入账，累计成绩决定档位、钱包决定是否能开火；花费不会降低历史累计，返分小于耗费、耗尽停止、玩家全灭仍失败。不要复制RevGame的具体成长阈值作为其它游戏默认值。

### 3. 先做具体实现，再执行必要动作

优先业务层组合已有门面，不先改框架快照。源码改动、Excel导表、Prefab绑定、材质/Shader、图集与GM一起组成可review的完整功能，不停在只有C#或只有JSON计划。

测试入口缺失时，在用户已授权开发/测试范围内补最小项目入口：实际动作、稳定只读状态、隔离夹具和复位。限定Editor/Development，注册/注销对称。没有运行实例时先编译和静态验证可完成的工作，明确剩余执行项。

### 4. 复用最快的可靠通道

已有会话优先RevMCP连续调用；零散Editor操作用live CLI；多项独立只读查询可合并，Unity变更/构建/场景/Play串行。能力发现与schema核对不可省。域重载后重新发现，不逐条短命启动MCP读大清单，不并行提交工单去“加速”战斗测试。

参考 [Unity编辑器实践](revgame-editor-practice.md)，跨接口执行交给 `revolution-ai-automation`。该Skill未安装时读取其官方源内容或使用已有CLI契约，不猜不存在的工具名。

### 5. 按证据等级验证

- 规则：真实Service与框架状态机/解析器，独立内存输入；命中、扣牌、伤害、积分、数量、拓扑、目标优先级都有差值断言。
- 玩家操作：实际EventSystem指针/UGUI能力，按钮是否真的启用、遮挡、成功提交；不能通过Button.onClick.Invoke或直接私有回调证明真实交互。
- 连续流程：正常布阵/换位/奖励入口，跨回合/场景交割，AI状态与生命周期。固定启发式策略要注明，不能称每帧LLM实时战术。
- 资源：冷PC AB、当前章按需加载、晚图集绑定、生成清单编译、实际平台manifest、重复进出清理。
- 视觉：真实截图和按时连拍GIF，参数/几何/材质检查辅助解释，不能只根据isVisible或GM成功断言美术满意。
- 性能/设备：固定输入、测量口径、CPU/GPU/内存/GC分开；Editor、Player、真机分别结论。无实测不承诺零GC、合批或手机帧率。

### 6. 失败、重试与范围变化

读取首次失败的作业、日志和状态，区分玩法、资源、测试夹具与工具故障。修复本次已授权范围后有界重跑，不降低断言、不无限重试。一次60局运行58胜2负不能改成全胜；测试期间新增工具Error也需保留。中断后分段补测可覆盖全部章回，但必须标明合并覆盖，不能冒充无中断战役。

自动化会自己消费手牌、目标和能源：每轮复位输入，清理不能依赖某个成功步骤才拿到的Id。取消/退出也finally清监听、Timer、Tween、池、资源租约、输入、时间缩放与临时存档，并等待安全Screen真正交付。

### 7. 交付与发布

报告说明当前最终实现、参考文件、修改范围、具体断言、实际轮数、新增Error、首次失败与修复、清理结果、截图/GIF和未执行部分。日期按数据产生时间，历史报告与最新版本明确分开。

尊重目标项目证据策略。RevGame要求文档只留HTML和必要图片/GIF，原始JSON/CSV/Profiler在忽略的 `.codex/work/`，不生成ZIP、`.codex/`不提交；其它项目按其用户/AGENTS规则，不能让Skill默认归档覆盖用户要求。

只提交本次授权源码/配置/资源/报告，保留既有用户改动。推送目的仓库与分支按实际remote核对，不能把origin当原作者；成功后远端SHA核对。Revolution Skills修改源为main的Skills，skill生成分支由官方发布工作流同步，不手工覆盖生成分支。
