# 按测试轻重选通道

AI 根据用户需求自动选：**轻量操作用 RevCLI，重量级测试用 RevMCP 的 `rev_run`**。用户明确指定时听用户的。

## 判定规则

满足下面**任意一条**就是重量级，用 MCP `rev_run`：

| 信号 | 例子 |
|---|---|
| 要一份 HTML 报告，带截图或 GIF | “测完给我出个带图的报告”“录个技能动图” |
| 步骤多，大约超过 5 步，或要跨帧等待、轮询状态 | 打完一整关、跑一套新手引导、Boss 全阶段 |
| 每步都要业务断言，失败要定位到哪一步 | “验证每次升级属性都对” |
| 中途失败也必须清理现场 | 测完要回档、关面板、还原 GM 改过的数据 |
| 要反复跑做回归或压测 | “这个流程跑 20 遍看稳不稳” |
| 用户说“完整测试”“验收”“回归”“出报告” | — |

其余都是轻量级，用 RevCLI：

| 场景 | 命令 |
|---|---|
| 调一两条 GM 看效果 | `runtime start` → `game gm <名称> 参数` |
| 点一下 UI、读一次状态、截一张图确认 | `game call ui.click` / `game call runtime.state` / `game call runtime.screenshot` |
| 冒烟确认刚写的脚本在跑 | `editor play` → `transform.get` 读回 → `editor stop` |
| 所有编辑器操作 | 搭场景、挂脚本、Prefab、UI、导表、打 AB、出包 |

拿不准时：**要报告就用 MCP，不要报告就用 CLI**。

## 为什么这样分

| | 轻量（CLI） | 重量（MCP `rev_run`） |
|---|---|---|
| 交付物 | 命令的 JSON 结果 | 一份 `中文标题_日期.html`，截图收进报告目录，动态效果合成 GIF |
| 失败处理 | 失败就停，现场由 AI 自己收拾 | 计划里的 `finally` 无论成败都逐条执行 |
| 步骤编排 | 一条命令一步 | 整份计划一次提交，内置断言和有界等待 |
| token | 零固定开销，最省 | 每轮有固定开销，但长测试只提交一次，总量反而更少 |
| 前提 | 有 Python 就行 | AI 客户端已配好 RevMCP |

长测试用 CLI 一步步拼也能做，但要 AI 自己记住每步截图路径、自己合 GIF、自己保证清理，步骤越多越容易漏，token 也越多。

## MCP 不可用时

客户端没配 RevMCP（`rev_run` 工具不存在）时，不要假装做了重量级测试，降级为：

1. 告诉用户“没检测到 RevMCP，用 CLI 降级执行，清理需要我逐步保证”。
2. CLI 逐步执行，每个关键步骤 `game call runtime.screenshot`，失败时也要把清理命令跑完。
3. 用 `rev.py evidence --directory <截图目录> --title <中文标题>` 生成带图报告；有动态效果再用 `rev.py gif` 合成。
4. 报告里写明是降级执行。

## 不要做的

- 不要用 MCP 跑一两条 GM：每轮都付固定 token，换不来任何好处。
- 不要用 CLI 一条条拼几十步的验收再手工凑报告，除非 MCP 确实不可用。
- 工具调用成功不等于测试通过，必须看业务断言。
