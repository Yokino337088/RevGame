# 代码与新手注释守则

新增或修改 RevGame 项目代码时，把阅读者当成第一次接触这个模块的同事。C#、Editor、测试工具、C++ 原生核心和项目服务端代码均按职责覆盖。先参考同类实现，再按下面的粒度写注释。

| 位置 | 每一处需要说明的内容 |
|---|---|
| 类、结构体、接口、枚举等类型 | 职责和边界、谁创建或调用、谁维护状态和何时结束。接口还需说明调用方可依赖的不变量。 |
| 每个字段、属性和常量 | 一条中文注释对应一个成员。说明语义、单位、范围、默认值或哨兵值。适用时说明所有者、是否可写、在哪个阶段更新、何时失效或清空。序列化字段需说明来源和配置影响。 |
| 每个方法、构造函数、重载和回调 | 说明入口、输入输出、调用时机与副作用。标明拒绝或失败的语义，特别是接受请求与实际完成的区别。生命周期方法说明资源如何成对取得和释放。 |
| 方法内部各职责段 | 在预检、状态提交、外部调用、跨帧等待、回调、失败恢复和清理等步骤前解释目的及次序。短方法也要让新人能从注释看懂实现意图。 |
| 重要算法内部 | 分段说明输入假设、单位或下标、不变量、边界条件、确定性与缓存失效。对容易误改的分支解释改错后会出现什么。 |

- C# 声明优先用 `/// <summary>`，必要时补参数、返回值和失败语义。实现中的关键步骤用邻近的中文行注释。C++ 与 Python 按该语言惯用形式写。注释随实现一起更新，避免逐行翻译赋值语句。
- 新文件逐一覆盖所有手写声明和实现段落。修改已有文件时，覆盖本次触及的类型、字段、方法及内部实现，补齐理解本次改动所需的相关契约。生成代码的永久注释写在可控模板或生成器中，按正常流程重新生成。框架快照和第三方代码遵守各自的维护边界。
- 所有方法体带大括号，方法签名的 `(` 与参数同行。每个 `if/else if/else` 的条件、左右大括号和代码体逐行展开。类、方法和属性的大括号也各自独占一行。格式适用 [AGENTS.md](../../../../AGENTS.md)。
- 提交前逐文件检查：本次新增或改动的声明是否都有中文说明，关键实现是否写明顺序和原因，失败路径是否与代码一致。代码审查把注释缺失或语义过期作为返工项。

## 项目中的阅读样本

- 远征占格和预判：模型写入口维护占格版本和缓存，AI 用调用者独立深快照。注释要解释为何不能在实战棋盘上试算，以及补子、换位或死亡会使哪些查询失效。参见 [缓存与反馈优化](https://github.com/Yokino337088/RevGame/commit/7706f7bf) 与 [新手导读](https://github.com/Yokino337088/RevGame/commit/0e41fcef)。
- 决斗帧与原生边界：说明逻辑帧单位、双席输入的封口顺序、下一连续帧、快照所有权、失败无写入、以及固定点运算。参见 [帧同步新手注释](https://github.com/Yokino337088/RevGame/commit/47324329)。
- Unity Editor 配方：对入口和写入步骤说明源、目标、重建范围、GUID、预检和清理。按 [Editor 代码规范](editor-code.md) 选址和验证。
