# 选择有效验证并交付框架结论

按改动选择能证明行为的检查。普通开发不自动跑满全部历史压力场景，静态格式或技能文档修改也不自动启动游戏。涉及实际游戏测试联动 [revolution-ai-automation](../../revolution-ai-automation/SKILL.md)；性能工作另联动 [revolution-performance](../../revolution-performance/SKILL.md)。

## 哪种改动需要什么证据

| 改动 | 最小有效验证 | 不能据此宣称 |
|---|---|---|
| 技能/文档/目录索引 | 内容、链接存在、路径/版本准确、技能校验器；移动资产检查 GUID | Unity 编译、Play 或业务已通过 |
| 六章纯规则、伤害、缓存、AI | 可用的既有 `RevGame_Client/Tests/CombatAttackRegression` 或对应规则检查；正常与拒绝前后状态 | 离线通过不代表图形、AB、真机性能通过 |
| 玩家业务入口、成长、暂停/保存 | 真实入口的正常与拒绝路径；受影响状态、资源/库存变化、退出/重入 | true/accepted、日志无报错不能代替业务后置 |
| UI/Prefab/场景/图集/Shader/字体/音频 | Unity 编译与字段读回；真实画面与绑定；资源变更冷 AB，首开与重入；动态效果 GIF | Editor 直读与单帧图不代表冷加载/动态/目标平台通过 |
| 流程与资源交割 | `IsTransitioning=false`、Screen/真实场景一致、面板/棋子可画；取消/失败清理 | EnterBattle/EnterEndless/ReturnHome 返回 true 只表示请求接受 |
| 无尽独有规则 | 独立 seed 与 isolated 局，棋心/成长/波次/存档对应断言；涉及共用模型时加远征回归 | 无尽策划建议值不是验收阈值，工作区实现不是已推送能力 |
| 九路围棋、联机和外部 Agent | 先核对棋规和拒绝无副作用；联机用真实连接验证双方已接受序号、指纹、终局、重连和清理。真实 Agent 单列合法性、超时与回退 | HTTP 200、单端动作成功或同机探针不能证明双端一致、真机或跨设备可用 |
| 原生决斗帧同步 | 执行真实双端或现有原生联调夹具，核对连续完整帧、双端快照/哈希、连招与回放恢复。变更二进制时记录实际 ABI 与装载结果 | 只跑 C++ 单侧或只观察 Unity 动画不能证明线上同步 |
| 性能 | 固定平台/种子/对象数/输入/分辨率/资源模式，基线与修改后同条件采样；业务与视觉同时保持 | 局部计时不等于整帧、Editor 不等于手机、实例化开关不等于收益 |

每条业务检查写成“前置 → 玩家共用入口 → 精确后置 → 拒绝无副作用 → 清理”。数量、ID、占格版本、HP/护盾/积分、阶段和引用只选与任务有关的项；别增加只匹配实现文字的测试。既有离线工程若本地缺 csproj 或依赖，说明可用范围，不能把目录里有源码当测试执行成功。

## 游戏测试的项目通道

**Unity 制作/导表/构建优先 RevCLI；实际游戏 GM/UI/跨帧回归按当前 AGENTS 优先 RevMCP。** 这项项目约束覆盖通用技能“轻量游戏测试默认 CLI”的示例。用户本次明确指定其它通道时按用户要求，同时保留断言、等待和清理。

1. 目标为 `RevGame_Client/UnityProject/RevGame.Unity`，MCP 入口为相邻 `Revolution.RevMCP/rev_mcp.py`。有现存连接时复用；否则按联动技能连接一份常驻 stdio，不逐条重启短命服务。若先需恢复编辑器连接，使用 RevCLI connect。
2. 执行真实 `rev_discover`。使用本次工具 schema 支持的 query/target 筛选，不凭离线清单或源码属性推定运行期注册。编辑态缺 GM 如实报告；启动 Play 后及编译/重载后重新发现。
3. 用 `rev_call` 调用实时注册的完整 GM 名、能力 ID 与参数；跨接口、多断言/等待/报告计划用 `rev_run`。查询直到完成时只轮询实时声明 readOnly 的能力，并设截止时间；不轮询/自动重放变更动作。
4. 多步计划包含业务 assert 与 finally。核对顶层 success、每步 response、等待结果、轮次、取消与清理，以及本次新增 Console/runtime Error/Exception。清理失败不能报整体通过。
5. 对话展示实际调用顺序、关键参数、目的、结果，例如“`rev_discover` 确认无尽 state/GM → `rev_call` 接受隔离局 → `rev_run` 等流程完成并断言/收尾”。实际仅用了其中一部分就只报告那一部分；直接 CLI / Python Hub 不能冒充 MCP 工具执行。

自动化入口参考 `Bootstrap/Diagnostics/GameGmCommands`、`Bootstrap/Diagnostics/Endless/EndlessAutomation` 与项目 `Editor/RevGame/ResourceBuild/Game*Automation`。使用 `UNITY_EDITOR || DEVELOPMENT_BUILD || REV_AUTOMATION` 的项目边界，owner 注册/注销对称。测试新局/存档/成绩必须隔离，不直接改 UI/FSM 私有字段、存档或预期数据造通过。缺能力时补最小受控项目接线，正常编译、重新发现后执行。

## 用缺陷闭环验证完整性

按 [框架缺陷闭环](../../revolution-ai-automation/references/defect-closure.md) 把本次策划条目映射到用例。按模式用现有规则检查和真实玩家入口，验证相关正常、拒绝与生命周期路径。跨模式共用代码修改后，在每个受影响模式挑可证伪的回归。复现记录必须带测试使用的配置、资源模式和隔离条件。

例如远征过场需要核对请求是否接受、实际就绪、场景/棋盘/手牌状态和返回清理。改到交接时，复跑原失效路径并检查连点拒绝、故障返回和重入。现有 `Assets/Editor/RevGame/Scenes/GameSceneTransitionChecks.cs` 可作为状态断言和源码定位入口。验证玩家点击与遮挡时使用真实指针链。冷 AB 首开按实际资源路径验证。

缺陷记录存 `.codex/work/<任务>/defect-closure.json` 或项目等价记录。HTML 写清关联用例、根因、修法和修前修后结果，保留未走到的步骤及收尾状态。功能开发或修复任务在证据支持时继续完成修复和回归。只委托测试或诊断时交付可复现的缺陷和修改建议。

## 场景与时间的关键断言

- 启动只保留一个 Bootstrap，一次框架初始化；StartScene 负责大厅/选关，GameScene 远征，EndlessScene 无尽。测试从正式入口与实际业务过渡，不从打开目标场景跳过首次资源链。
- 普通 Editor Play 直接进入大厅。回归首次序章和教学时，先发现并显式开启隔离首启 `game.story.test-arm`（`flags=0`），核对自动剧情与实际就绪，退出后 `game.story.test-disarm`。只验单篇内容时可发现 `story.preview`，按当前篇章资产和实时参数调用。
- 异步请求被接受后等待 `IsTransitioning=false`，再核对目标 Screen、`RevScene.CurrentName`、资源和可画状态。六章遮挡等背景、81格与六张手牌可画；无尽等 `EndlessHudPanel.PrepareAsync` / `EndlessArena.Ready` 和实际手牌/棋子资源，不能套用六张手牌数。
- 第一次加载测试不先把所有图集预载进缓存。记录具体资源模式、冷启动方式和是否真正卸载/重启，避免热缓存冒充首屏修复。
- 暂停与域停 Tick 不等价。按六章/无尽实际计时门禁验证：需冻结的模拟/刷怪/存活计时冻结，允许继续的表现或现实时间按契约；退出恢复本次改变的时间、相机、输入和短效。
- 失败、取消、重复请求与晚到资源不应交付到失效域或新局；旧回调只能清理。需要覆盖这些路径时设有界取消/超时，不无限重试。

## 报告与框架可行性

实际业务测试按照自动化技能交付中文 HTML；视觉测试附真实截图，动态附 GIF。文件名用 `<中文标题>_<YYYY-MM-DD>.html`，日期取数据产生当天。文档目录只保留报告与必要媒体；原始 JSON/CSV/日志/参数/临时脚本在 `.codex/work/<任务>`，不生成 ZIP，不自动 SaveProfile，不新导出 `.raw/.data` 或内存快照。

交付说明围绕结果，包含：

- **需求结果：** 哪个用户可观察行为改变，修改所在功能与为何放这一层。
- **框架验证：** 本次实际使用的 Rev 门面/项目适配、目标是否支撑；必要的项目接线与仍需回源框架解决的缺口分开。
- **证据：** 执行环境、关键输入/断言、失败与清理结果、文件链接；编译/离线/Editor Play/真实 AB/独立 Player/真机分别陈述。
- **限制：** 未执行项、目标设备缺失或待解决的能力边界。旧成功数据不冒充新增结果，也不为了“验证框架”扩大本次任务。

只改技能时交付技能校验与引用检查即可；不为证明文字生成能力重建 AB 或影响当前 Play。

## 提交与只推指定目录

1. 提交不是技能加载的默认动作，遵循当前用户授权。开发完成后检查差异、暂存区、分支、远程和待推送提交集合。
2. 仅暂存本任务明确文件。用户要求“只推这个 skill 文件夹”时，仅 `.codex/skills/revgame-development/`；报告、原始证据、其它技能和项目协作文件不夹带。可用显式 pathspec 的 add/commit，并核对新提交实际文件集合。
3. 推送前确认远程真实 HEAD 与祖先关系；存在其它未推送提交时不能仅凭本次暂存范围说“只推这一目录”。使用能隔离指定内容的普通提交/分支方式，保留原工作区，不 reset/rebase 用户已有工作、不强推。
4. 远程若已推进，先读取新状态并确定安全的合入方式；不为完成推送清掉 dirty 工作区或改变无关内容。推送受阻如实报告具体原因。
5. 完成后读取远程提交标识，核对路径集合与本地提交相同，报告提交号、分支和推送结果。`.codex/work`、连接配置与凭据不入库。
