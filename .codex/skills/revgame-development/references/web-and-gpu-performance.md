# RevGame Web 与棋盘渲染性能

## 大厅资源准备

- 首页、选关和战斗首屏的必要资源走现有场景交接。仅在大厅可交互后，`HomePanel.BrowserWarmup` 按设置、对战、无尽登记三个高频入口。读取正式面板路径与显式等待的 `EndlessMenu` 图集，每次只处理一个候选，成功留在本次大厅域，失败提前归还。先测冷开率、实际依赖和驻留，再决定是否给其他域增加候选。
- 在 Web Player 以同一批 AB、相同网络条件和独立浏览器配置测从真实点击到可见。对照资源请求的时间，另量实例装配和打开动画。旧包与预热包的无尽入口各三次，截图采样上界中位数 2.22 → 0.99 秒，提前传约 1.77 MiB。提前传输的体积是成本，不能把它当作节省的流量。 [11 月 21 日实测](../../../../RevGame_Client/文档/战斗性能优化规则/web端性能优化/RevGame_Web端性能优化实践_2026-11-21.html)
- 框架下载调度与项目预热策略职责分开。普通 Web Player 的独立 AB 依赖可以少量重叠，实际 HTTP 请求受框架限额，同名请求合并。热更缓存 key、版本化 URL 和图集首次绑定分别核对。 [框架浏览器 AB](../../revolution-framework/references/webgl-delivery.md#浏览器-ab-的冷开与依赖调度)

## 网页战斗

- `RevGameFullscreen/index.html` 让 CSS 画布满屏，绘制缓冲约束在约 144 万像素。普通浏览器远征用 `BoardView.Feedback` 的 14/24/12 同屏表现额度和每帧 3 条新弹道，其它宿主保持自己的配置。帧差测试固定棋局、采样阶段、DPR 与实际尺寸，核对真实攻击数及 P95/P99。第 4 章 81 棋的像素主对照 49.9 → 59.1 FPS，仍有超过 50 ms 的帧，第 6 章 48 棋的多轮结果有明显波动。稳定 60 FPS 继续按目标设备验收。
- 分清真实目标帧率和 CSS 画布显示大小。高 DPI 用普通入口实测点击相同棋格、落子、全屏和大小变化。没有 GPU 用时的浏览器帧间隔不能直接标成 GPU 时间。

## 棋盘挡住背景

- 远征第 2～6 章世界背景使用 `ZTest LEqual` 并更靠后。在当前前向正交相机上，`BoardView.BackgroundDepth` 合并 **实际九宫格内芯**，从当前图集按真实 UV 读 alpha。命令在 `BeforeForwardOpaque` 提交，只写深度。用 ZTest 跳过稳稳遮住的背景片元，缝、软边与其它区域沿用各章原 Shader。
- 世界深度靠近背景，保持原来的前景排序。第 1 章 Shader 同时兼容原 UI 用法，沿原路径。图集、渲染器或相机条件不成立则走原渲染，胜利演出移动格层时撤销。退出先摘掉命令，再归还网格和材质引用。
- 分包使用 `Material/Board/BackgroundDepthMask`，真实 Shader 归 `shared_shaders`，对应材质归 `material_board`。复测从第 4 或第 6 章实际入口进入，成对比较同一帧的颜色，点查遮挡范围和演出恢复，退出核对相机命令清理。跨平台核对 Shader 编译与目标 AB 冷启动。有有效 GPU 数据时才报告 GPU 毫秒。 [框架 GPU 专题](../../revolution-performance/references/gpu-rendering.md#用真实不透明覆盖提前挡掉背景)

- 2026-11-22 的 D3D11 真 PC AB 捕获在 960 × 540 上比较同一帧。第 4/6 章最终颜色差为 0，单独核对遮挡时分别滤掉 92,144 / 123,358 个背景像素。胜利格层撤挂、复挂和退场已测。这些数据是遮挡面积与画面证据，GPU 时间以另测结果为准。
