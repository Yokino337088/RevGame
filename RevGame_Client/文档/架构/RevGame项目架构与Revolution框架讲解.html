    GUIDE / 01

    先把词弄懂

    读 RevGame 先找谁拥有数据、谁推进它、谁显示结果。远征的一次落牌由 BattleLogic 调用 IBattleService，服务通过 RevEvent 告诉界面发生了什么。无尽沿用域与服务分工，九路围棋改为逐手提交，八角笼通过连续整帧推进原生内核。

    名词在项目里怎么理解例子
    服务 Service拥有一组业务状态、查询和命令。调用方通过明确的服务契约读写。IBattleService → BattleService
    域 Scope / Domain与一段业务阶段关联的生命周期，退出时回收由域持有的 Logic、面板和其他已登记对象。GameDomain.Battle、GameDomain.Endless、GameDomain.Pvp
    Logic把输入、计时、事件和服务接在一起，随域启动与停止。BattleLogic、PvpLogic
    事件 Event广播已经发生的事实，订阅者各自消费并按 owner 清理。Events.PiecePlaced、Events.PieceDied
    状态机 FSM管理状态和切换条件。流程、普通敌棋和 Boss 各自拥有所需的状态机。GameFlow、EnemyAI、BossAI
    对象池反复使用的格子、棋子、弹道或反馈归还后供下次取用。RevPool、PieceView
    导表把策划工作簿变成可加载数据和强类型 C# 产物，运行时统一校验。Generated/BattleDataTables.cs、GameConfig
    Presentation把阶段与显示接起来，按业务状态开关面板与场景节点。BattlePresentation、GamePresentation
    固定步长每次规则推进使用相同长度的时间片。决斗中相同的初始状态和输入流还必须得到相同结果。远征 Balance.BattleSimulationStepSeconds，决斗 DuelConfig.FrameMs
    从名字找到归属Revolution 命名空间里的 RevServices、RevScene、RevEvent 是框架入口。RevGame 命名空间里的服务和规则由本项目实现。

    整体架构与目录

    Unity 宿主启动 / 流程 / 服务接线 / 界面

    Bootstrap装配

    GameBootstrap 初始化框架、注册常驻服务、启动 GameFlow，开发版本还装配验证入口。

    Flow编排

    GameFlow 组合 FSM、域和异步加载。各模式的 Logic 负责计时、操作门禁或会话轮询。

    UI / View输入和显示

    转发点击和触控，按事件、只读查询或确认快照更新显示。视图的插值、对象池与动画有各自的生命周期。

    输入和结果远征、无尽走服务命令。围棋走有序棋谱。决斗从权威历史取得完整帧，再读回原生输出。
    资源和生命周期Revolution 提供场景、面板、计时、事件和资源门面。项目流程明确每种模式的打开、等待与释放时机。
    可分开验证的规则与传输业务层 / 共享 C# 棋规 / C++ GameCore / Fantasy

    远征与无尽

    棋盘和走法由模型与规则实现，具体回合或波次由各模式服务持有。两种模式分别校验各自的数值、成长与存档。

    围棋

    GoCore 提供规则和可重放的棋谱，Unity 与 Fantasy 服务端共享相关源码。PvpService 负责客户端状态、Agent、回执和接入模式。

    原生决斗

    RevGameCore 以 C ABI 接受整帧并输出结果。独立原生工程能在无 Unity 的环境构建与跑断言。

    GUIDE / 03

    从 StartScene 到进入战斗

    1. GameBootstrap.Awake正式入口是 StartScene。GameBootstrap 执行顺序为 -100，并在跨场景时保持常驻。它设置横屏 UI，调用一次 RevInitialize.Initialize()，注册图集、音频、剧情、进度、各模式与流程等服务。
    2. GameBootstrap.Start用 RevTask.Yield() 给场景表现留出订阅时机，再调用 GameFlow.StartAsync()。
    3. GameFlow.SwitchSceneAsync打开并从旧域分离 LoadingPanel，启动时校验数据表。加载所需图集、预热预制体，必要时经 RevScene.LoadAsync 更换场景。
    4. FlowState.OnEnter通过 FSM 交割业务状态并用 RevScope.Enter 打开对应域。进入远征先 BeginCampaign 建首回合，再启动 BattleLogic，交割后广播 ScreenChanged。
    5. GamePresentation.WaitUntilReadyAsync背景、棋盘和手牌等实际可见后才收起过场。EnterBattle、ReturnHome 返回成功代表请求已接受，完成状态要等 IsTransitioning == false 并核对目标 Screen。

    启动装配 · 异步场景交接 · 场景验收入口

    GUIDE / 05

    用 RevServices 装配和取用服务

    启动入口注册远征服务接口、无尽与 PvP 服务、GameFlow 等常驻能力。使用方在业务入口调用 GetRequired，这样能在缺少注册时立刻看到原因，注销由注册 owner 管理。

    // GameBootstrap.Awake 中注册，默认首次取用才创建实例。
RevServices.Register<IBattleService, BattleService>(owner: this);

// 远征业务调用方按接口取用当前有效实例。
IBattleService battle = RevServices.GetRequired<IBattleService>();

    BattleService 的 partial 为什么分目录

    多个 partial 共同组成同一个类和实例。看公开契约时打开 Contracts/IBattleService，读执行路径再按职责跳转。战斗服务目录

    子目录它回答的问题
    Simulation战斗的时间如何累积、一小步怎样推进、何时判回合结果。
    Preparation落牌、换位、刷新手牌、准备增益怎样校验和提交。
    Progression章节怎么开局、回合如何接续、何时生成和领取奖励。
    Support伤害、围困、增援、战报等由哪条规则管线集中提交。
    AI / Diagnostics状态机怎样接进模拟，固定输入与开发入口怎样触发真实行为。
    GUIDE / 06

    流程、域与 Logic

    GameFlow 管业务屏幕

    GameFlow 用 RevLightFSM 管理首页、选关、远征、无尽、PvP 与退出。RevScene 管 Unity 场景。同一场景可以容纳首页和选关，同一 PvP 屏幕也能跨围棋与决斗场景。

    域决定谁在何时收尾

    FlowState 进入时开域，退出时关域。域管理已经归属该域的 Logic 和面板，常驻服务持有的网络、原生句柄、预热租约仍由各自所有者显式释放。过场遮挡从旧域分离，确保下一屏就绪前仍能覆盖画面。

    Logic 驱动该域的工作

    Logic它负责什么
    BattleLogic每个远征固定步触发一次 OnFixedTick。按过场、战斗阶段和教学状态控制时间与玩家动作，再交由服务。
    EndlessLogic读取独立的无尽步长，控制过场门禁，监听后台与退出并交给服务保存。
    PvpLogic轮询围棋、房间与决斗服务，发现权威决斗 ID 后请求 GameFlow 切决斗场。
    GUIDE / 07

    事件：模块之间怎么通话

    以远征为例，输入调用、状态读取和事实事件各有自己的方向。

    方式方向什么时候用例子
    调用 Logic界面 → 规则玩家做了一个操作RevLogic.Get<BattleLogic>().PlayCard(...)
    读服务状态界面 ← 规则需要“现在是什么样”battle.Phase、battle.Hand、battle.CardsRemaining
    订阅事件界面 ← 规则需要知道“刚刚发生了什么”RevEvent.AddEventListener(Events.PiecePlaced, ...)

    事件名全部集中在 Core/Events/Events.cs，都是 const string。规则层发事件，界面层订阅；规则永远不知道谁在听。

    // 发送（BattleService 内部）：只发“事实”
RevEvent.DispatchEvent<int>(Events.PiecePlaced, piece.Id);

// 订阅（BattlePresentation.OnEnable）：必须带 owner
RevEvent.AddEventListener<int>(Events.PhaseEnterBattle, OnBattle, owner: this);
// 退订（OnDisable）：按 owner 一次移除，不会漏
RevEvent.RemoveAllByOwner(this);
    订阅必须有主人每次 AddEventListener 都带上 owner，并在对象销毁 / 关闭时 RemoveAllByOwner。无主订阅会让旧对象在下一局继续收事件——这是最典型的泄漏。

    事件目录（核心部分）

    事件谁发谁听
    ScreenChanged(屏幕)GameFlow.ChangeGamePresentation（开/关面板与棋盘）、GameAudio（背景乐）、GameSpriteAtlasService（图集租约）
    PhaseEnterPrepare / Battle / Settle / RewardBattleServiceBattlePresentation（开关面板）、BoardView、PreparePanel、BattleHudPanel；Settle 另有 GameAudio（胜负音）
    PiecePlaced(棋子Id)BattleService（玩家落牌、援军、敌方增援）BoardView（创建 PieceView）、GameAudio（落子音）、BattleHudPanel
    PieceMoved / PieceHpChanged / PieceDiedBattleServiceBoardView（位置、血条、死亡动画）
    PieceAttacked(攻击信息)BattleService.AttackBoardView（出手动画与弹幕）
    BattleHit(伤害信息)BattleService.DamagePieceBoardView（飘字、受击）
    DamageResolved(棋子Id)BattleService.DamagePieceGameAudio（受击音）
    BattleEventTriggered / BattleLog(文字)BattleService（战斗增益事件、战报）BattleHudPanel（右栏弹幕与战报）
    PieceMerged(棋子Id)BattleService（三合一升级）BoardView、GameAudio、BattleHudPanel
    GoStateRefreshedBattleService.RefreshGoStateBoardView（刷新气、眼、被围显示）
    HandChanged / HandRerolled / SelectionChangedBattleServicePreparePanel、BoardView（刷新手牌与落点提示）
    PreparationBuffsGrantedBattleService.PreparationBattleHudPanel（弹幕提示）
    EnemyDeployed(棋子Id, 意图)BattleService.EnemyDeploymentBattleHudPanel（敌方落子弹幕）
    GameFinished(是否胜利)BattleService.ProgressionGameFlow（返回主界面）
    BattleEnded(胜方)BattleService.EndBattle回合结果事件，面板切换由 PhaseEnterSettle 驱动
    想知道某个事件有谁在听？在仓库里搜 Events.事件名：DispatchEvent 是发送方，AddEventListener 是订阅方。
    GUIDE / 08

    三条完整链路

    把前面的概念串起来。每条链路都对应真实代码，你可以按步骤逐个文件对照阅读。

    链路 A：玩家落一张牌

    1. 选牌、点格子PreparePanel / CardItem → BoardView选牌调用 BattleLogic.SelectCard(id)（只改“选择”，不扣牌）；点格子时 BoardCellView 把点击交给 BoardView。
    2. 统一入口View/Board/BoardView.cs → Flow/Logic/BattleLogic.csBoardView 先检查 GameFlow.IsGameplayBlocked（过场中不接受操作）；若正显示攻击范围，这次点击只负责收起；否则调 BattleLogic.ClickBoard(pos)。界面到此为止，不接触任何数据。
    3. 服务判定Services/…/BattleService.Placement.csHandleBoardClick(pos) 的判断顺序是：① 点到己方棋子 → 选中 / 取消选中；点到敌棋 → 拒绝；② 点空格且已选中棋子 → 换位（BoardModel.Move，放不下则拒绝）；③ 战斗期没选棋子 → 拒绝；④ 准备期 → 补眼模式调 TryPlaceEyeStone，否则调 TryPlayCard → PlaceCard：校验阶段、落子额度、整块空间，再 Place 占格、检查三合一升级、继承准备增益、刷新气眼。
    4. 失败也有交代任何一步不合法，服务写 LastError 并发 SelectionChanged，棋子/手牌/额度保持原样，界面直接显示原因。
    5. 广播事实RevEvent成功则发 PiecePlaced、HandChanged、SelectionChanged（及 GoStateRefreshed）。服务到这里就结束了。
    6. 各自反应BoardView 从 RevPool 取出 PieceView 并 Bind；GameAudio 播放落子音；PreparePanel 刷新手牌与剩余额度。它们互不认识，也不需要。

    链路 B：战斗中的一小步

    1. 固定节奏BattleLogic.OnFixedTickRevTimer 每个固定步长触发一次；若流程处于过场则直接返回；否则 Battle.Tick(step)。
    2. 攒时间、切小步BattleService.Tick准备阶段只推进“增益发放”计时；战斗阶段把传入的时间攒进累加器，攒够一个固定小步就循环处理：ResolveOneStep → 敌方增援检查 → 准备增益的战斗效果 → 自动战斗事件 → 通关辅助 → 判断是否结束。帧率再高也不会多算。
    3. 先我方，后敌方ResolveOneStepRefreshGoState → StepSide(Player) → RefreshGoState → StepSide(Enemy)。各阶段按固定顺序读写占格和气眼。
    4. 敌方由状态机决定StepEnemyAI → EnemyAI.Tick每颗敌棋的 RevHeavyFSM 在自己的 OnUpdate 里感知（死亡 / 零气 / 有射界 / 移动冷却），切换到 Attack 或 Advance，再执行；执行时只能通过 IEnemyAIOwner 调用服务的原子动作。
    5. 统一扣血出口Attack → DamagePiece先发 PieceAttacked（供动画），再由 DamagePiece 结算伤害（锁死倍伤、护盾、减伤等），发 BattleHit、PieceHpChanged、DamageResolved；死亡则发 PieceDied 并把该敌棋的状态机切到 Dead。伤害只在这里算一次。
    6. 判胜负EndBattle擒王、一方全灭或超时后：停掉敌方状态机，进入 Settle 阶段，发 PhaseEnterSettle，BattlePresentation 据此打开结算面板。

    链路 C：从选关进入战斗

    1. 点击章节LevelSelectPanel → GameFlow.EnterBattle(chapter)检查未过场、处于选关屏、章节已解锁，通过则置 IsTransitioning 并开始异步切换。
    2. 过场与预热GameFlow.SwitchSceneAsync打开 LoadingPanel → 预载战斗图集 → 资源预热 → RevScene.LoadAsync(GameScene) → 预热对象池。
    3. 交割FlowState.OnEnterRevScope.Enter(Battle 域) → BeginCampaign(章节) 生成首回合 → RevLogic.Start<BattleLogic>()。
    4. 画面跟上ScreenChanged → GamePresentation 显示棋盘；BoardView 用对象池创建 81 个格子与开局棋子；BattlePresentation 打开 HUD 与准备面板。

    界面与表现层

    面板（UI/Panels）

    [RevUIPanel] 声明资源和层级，[RevBind] 接入预制体节点。OnBindView 装配，OnRefreshView 更新显示，交互回调转发给业务。以远征准备为例，开始按钮交给 BattleLogic.BeginBattle。PreparePanel 源码

    面板谁打开作用
    HomePanel · LevelSelectPanelGamePresentation主页与章节选择
    LoadingPanelGameFlow全屏遮挡与进度，失败时显示原因与返回按钮
    PreparePanelBattlePresentation准备期：6 张手牌、刷新手牌、开始战斗、跳过
    BattleHudPanelBattlePresentation战斗中：进度、战报、增益与敌方落子弹幕、返回
    SettlePanel · RewardPanelBattlePresentation回合结算、章节奖励三选一

    面板的三条规矩：远征交互转发给 BattleLogic；状态用“事件触发 + 低频刷新”获得，不在 Update 里每帧读写；打开者（Presentation 或 Flow）负责在加载回调里再次核对阶段，过期面板直接关闭。

    棋盘与棋子（View）

    • BoardView是事件的主要订阅者：PiecePlaced 创建棋子、PieceHpChanged 更新血条、PieceDied 播死亡、PieceAttacked 播出手、GoStateRefreshed 刷新气眼显示。它不做任何规则判断。
    • PieceView声明 [RevPoolPrefab(…)] 并实现 IRevPoolable，所以由 RevPool 创建和回收。回池会停用物体、Awake 不会再执行，因此动画在 OnEnable 启动、OnDisable 停止（RevTimer.Every 换帧、RevMono.AddUpdate 做移动插值）。
    • BoardView.Feedback / FairFeedbackBuffer / BattleEffectView管飘字与弹道的数量预算和回收，保证密集战斗时画面可读。数值预算见《战斗性能优化规则》。
    • GameAudio订阅事件，调用 RevSound.Play / PlayBgm 播放音效与背景乐。
    异步回调最常见的坑对象池和面板都是异步取得的。回调到来时棋子可能已经死了、回合可能已经换了、面板可能已经关了。所以回调里必须带“代次（generation）”或“版本号”核对：不匹配就直接回池或关闭，不要补播。BattleHudPanel.OnEnemyDeployed 就是示范。

    动画库的分工

    棋子帧动画用 RevTimer 切换精灵；弹幕、提示条、缩放等补间用 DOTween。DOTween 的对象由创建者负责在回池时 Kill，不要 KillAll。

    不要这样做

    • 保持规则与引擎依赖的边界。共享棋规和原生模拟的输入保持独立，Unity 对象由宿主与表现层持有。
    • 界面通过当前模式的业务入口提交操作。远征经 BattleLogic → IBattleService，围棋经 PvpService，决斗意图由权威端封入整帧。
    • 不要在 View 里重复结算伤害。画面只播放事件带来的信息。
    • 不要订阅事件不带 owner。不要创建无主计时器。
    • 不要用 Resources.Load / File.ReadAllText 读资源。一律走 RevResManager 的逻辑路径，数据表走 RevDataTableManager。
    • 不要把策划数值写死在代码里。放 Excel 并加校验。
    • 不要手改 Generated/ 和 Revolution/。前者由导表生成；后者是框架快照，需要改能力请回源仓库。
    • 业务拒绝带回具体原因。远征入口可查 LastError，围棋查 Status，决斗查回复和 DuelError。
    • 不要在热路径里 new List、FindObjectOfType、LINQ。复用缓冲，缓存引用。
    • 不要写单行 if。项目规范：if 后的语句必须用大括号并换行。
    • 不要把 async void 用在业务方法上。它只允许出现在按钮 / Unity 回调这类“无法 await”的边界，且要自己收口异常。

    远征、无尽与资源如何各自演进

    六章远征把规则、反馈与演出接在同一条线上

    常规棋子、玩家自动行动、助阵和 Boss 在各自目录里决策，实际占格由 BoardModel 提交。气眼和围困的缓存随占格版本、加气或免疫变化失效。AI 试阵用独立深快照，实际动作仍由服务校验与提交。九种棋子可以有不同出手条件、射界和协同行为，最终伤害走 ResolveDamage。

    Boss 回合由 GameFlow 编排入场与击败演出。BossSkillCatalog 按章校验六个通用槽和四个专属槽，BossAI 驱动蓄力、命中和收招。预警画在 View，伤害按命中时的实际占格结算。积分、死亡、结算由服务提交，飘字和弹幕只消费事实。技能池 · Boss 状态 · 战斗性能规则与证据口径

    无尽是单独的规则域

    GameFlow.EnterEndless 装载 EndlessScene 和无尽资源，EndlessLogic 按 EndlessConfig 的步长驱动 EndlessService。一局围绕棋心、持续敌潮、领主奖励和单卡升级运转。拖牌命中棋盘或吸附指定主力只是输入，服务负责验证、消耗牌和提交升星。轻量 ECS 在服务内部组织移动、战斗与死亡等热路径。EndlessArena 读取结果并驱动画面。

    无尽存档随该模式管理。切后台时由 RevAppLifecycle 通知 Logic 暂停并保存。EndlessMusicPlaylist 持有当前、下一首及淡出的音频租约，异步预载下一首并在交接后释放旧曲。无尽服务 · 单卡入口 · 音乐轮播

    剧情、鸦鸦与移动端如何复用同一流程

    大厅小屋和鸦鸦由 LobbySceneView 接入，GameFlow.Story 选择篇章、处理解锁和场景背景就绪，StoryPanel 消费剧情数据。远征和无尽各有一个鸦鸦反应 Logic，根据该域内已发生的战况选择台词，差分图集按需加载。围棋里的提示、劝诱和结算表情由 PvP 自己的表现代码处理。

    九路围棋的棋规、联机和 DeepSeek

    九路围棋按手提交。 GoCore 持有棋面、轮次、提子、劫与计分。当前对局配置有 68 手落子上限的自动计分路径，棋钟由 GoClock 跟随已接纳命令。对局提交一手得到新的棋面，再由 PvpPanel 与 PvpBoardView 绘制。八角笼决斗采用后面章节里的连续帧，每一帧都可表达两席操作。

    入口一手棋怎样成为双方的事实
    本机人机PvpService.SubmitActor 校验并应用命令，本地战术搜索生成的动作也走这一入口。
    局域网通过 UTP 直连。当前行棋席预检后向对端发送本手，双方按座位、序号与前后棋面指纹应用相同棋谱。切入决斗后由黑方宿主封帧。
    Fantasy 服务端客户端走 FantasyGoTransport。服务端房间维护座位、棋谱与时钟，提交时检查席位、序号、合法性，再返回权威状态。

    服务器匹配先按场次和规则文本分队列，再在同组按棋力距离找对手。GoMatchPolicy 用双方中较短的等待时间放宽匹配窗口。Elo 变化由围棋房间结算，客户端把更新后的棋力和已处理的房间标识写入本机档案。排队与房间 · 匹配与 Elo

    DeepSeek 代走。 GoAgentPosition 从当前局面构造合法动作候选及气口等信息。PvpService.Agent 在回包时核对当前棋面、席位和请求代次，解析并映射到合法候选，再走 SubmitActor。失败走项目既有的重试或本地兜底分支。玩家、Agent、电脑共用业务提交和传输确认。

    从按下跳跃到提交第 103 帧

    早期联机每一帧都等齐两席输入，客户端收到上一次回包才编号下一轮。往返延迟一旦超过 50 ms，等待就会压低模拟速度，画面也跟着到包间隔走。11 月 10 日改造后，权威按单调时钟封帧，意图先进各席邮箱，客户端按连续游标取历史。到包抖动交给独立播放头消化。

    1. 发起挑战并等待两席 Ready劣势席达到手数与分差门槛才有正式挑战入口，权威端再核对棋谱或棋面。GameFlow 经 RevScene 从围棋场切到决斗场，原房间仍然有效。场景到位后各端发送 Ready，readyMask == 3 才能开打。
    2. 采样意图并编号键盘和 HUD 共同调用 SetDuelInput。每席用 6 位表示方向、招式与跳跃。联机 inputFrame 是连接内单调输入序号，afterFrame 是客户端已执行的最后连续帧。举例，上行序号 17 可以被封进逻辑帧 103。
    3. 权威按节拍取两席输入Fantasy Gate 定时唤醒 AdvanceNetwork，LAN 由黑方宿主推进。DuelInputMailbox.Stage 按序号接纳。Take 允许方向短时沿用，过期回中，跳跃边沿取一次，招式可在四帧窗口内等待恢复期。双席已就绪时，即使一席静默也由权威生成完整帧。一次唤醒最多追三帧，超出预算时重排墙钟上的下次封帧时间。
    4. 先执行裁判，再发布整帧Seal 把黑、白输入固定顺序打包，DuelCorePipe.Append 用版本化的小端整数写入 C ABI。原生检查连续帧号与包长，计算后返回同号快照。裁判成功才把这一帧放进历史。单机人机走同样的裁判接口，本机宿主收齐两席的当帧输入再提交。
    5. 用游标补齐并执行确认副本DuelReply 从请求的 afterFrame + 1 起回连续历史，单批至多 64 帧。AcceptDuelReply 核对局 ID，略过重叠的已执行段。若回复从缺口之后开始，本端保持当前游标，下一轮仍从缺口前请求。
    6. 用封帧回执确认意图追到最新权威帧的回复才带 inputAckFrame 与本席 inputAckSequence。仍缓冲的招式还有 pendingActionSequence 和 pendingActionUntil。例如回执处理到序号 17，而 17 的招式还在等恢复期，预测重演时仍以权威给的到期帧保留它。

    一帧里面，C++ 按什么顺序算

    GameCore_Write 接收开局配置或整帧。DuelWorld::Advance 先检查帧号和输入，再按固定黑白顺序处理移动与招式。ResolveDuelDamage 先收集两席的命中与伤害，再统一提交，因此同一帧双方可以互相命中甚至同时倒地。最后推进帧号并产出快照。队列容量不足有返回码，C# 桥核对写入、读回长度和帧号后更新本端快照。

    坐标采用千分格定点数，血量、能量、硬直和动作年龄是整数。开局从同一决斗 ID 派生种子，原生实例各自持有随机状态。当前招式伤害按确定规则结算，随机状态仍进入指纹和检查点。修改命中距离或跳跃参数时从 Duel.v1.json 生成配套配置，联机门禁以配置及协议指纹识别版本。封帧与邮箱 · C# 桥 · C ABI · 模拟顺序 · 决斗配置

    确认快照、预测回滚与绯焰鸦鸦的画面

    DuelPlayback 保存最近 32 个已执行的显示快照。联机播放头以落后约 1.5 帧为目标，在相邻确认快照之间插值。发生积压时可以跳过过时画面并重定位播放头。确认副本仍按顺序执行每一个逻辑帧。

    1. 建立确认锚点客户端先执行新到的权威帧，再用同帧输入回执重建本席邮箱，保存该帧的完整原生检查点。连续补帧尚未追到最新时，等下一份匹配回执再建立新锚点。
    2. 在独立内核里回滚与重演DuelPrediction.Rebuild 将沙盒恢复到锚点，按上行顺序重演待确认输入，并可预演尚未发出的按钮。本机向前最多试算四个固定步，远端的假设只取最近确认的方向。被回滚的是这个沙盒。
    3. 读取本机运动例如按跳后，预测沙盒先给出本机离地高度。PvpDuelView 只取本机坐标、离地高度与跑动朝向。血量、能量、出招、命中、对手、相机和胜负依旧来自确认播放流。
    4. 按同一帧纠偏确认锚点推进时，用同帧比较预测位置与确认位置。小偏移约 85 ms 衰减，大偏移直接对齐。掉线、失焦、长追帧、锚点超时或输入日志溢出时停用预测，画面继续使用确认插值。

    显示快照已执行的帧号、两席坐标、血量、能量、招式状态、命中、胜负与指纹。画角色、HUD 与特效。播放窗口容量独立于权威历史。

    原生检查点已执行帧的完整模拟世界，包括隐藏状态。保存与恢复要求 FIFO 排空，恢复校验对局和规则，基线清掉旧命中。让隔离沙盒或录像实例从该帧后的下一帧继续。
    逻辑录像决斗 ID、配置与版本、步长、封口后的两席输入，以及逐帧期望指纹和结果。DuelReplay.ReplayInto 复用 Append 并逐帧比对。人机回放直接重用录下的电脑输入。

    在线恢复沿用连续游标。服务端识别席位掉线后暂停定时封帧、清理未封口输入；兼容的房间连接恢复后重新 Ready，客户端从当前已确认游标补历史，然后重建预测锚点。LAN 正式链路由黑方宿主持有裁判和历史，当前重入入口针对 Fantasy 服务端。录像已有序列化及回放 API，房间续局走历史游标，检查点用于原生世界恢复。录像实现 · 检查点实现 · Gate 与房间时钟

    出现分歧时先对齐帧号先确认对局 ID、协议和规则版本，再找两席最后共同匹配的采样帧。用其后的权威输入和同一版本内核重放，在逐帧指纹首次不同的位置对照输入、快照和隐藏状态。预测位置发生短暂纠偏属于表现层，可以用当时的确认帧号和指纹判断权威副本是否推进。
