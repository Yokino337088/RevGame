    GUIDE / 01

    先找当前模式的规则入口

    远征的一次落牌从面板和棋盘转发到 BattleLogic，由 BattleService 改棋盘，再由 RevEvent 通知 View。读无尽、九路围棋和八角笼时仍然先找谁接输入、谁提交结果、谁画出来，但这三步落在各自的服务与内核。

    模式谁推进规则画面从哪里拿数据
    六章远征BattleLogic 调 IBattleService，由服务提交占格、气眼、伤害与回合。BoardView 与战斗面板读事件和服务状态。
    棋阵幸存者EndlessLogic 调 EndlessService，服务持有波次、棋心、卡牌与成长。EndlessArena 和无尽 HUD。
    九路围棋PvpService 提交一手动作，GoCore 判棋规。PvpPanel 与 PvpBoardView 读取当前棋面和回执。
    八角笼决斗DuelAuthority 封帧，DuelWorld 推进裁判、客户端确认副本和预测沙盒中的各自实例。PvpDuelView 采样 DuelPlayback，可叠加本机预测运动。
    GUIDE / 02

    半小时入门，先读五个文件

    1. GameBootstrap.cs读 Awake 中的 RevInitialize.Initialize 和服务注册，再找 Start 调用 GameFlow.StartAsync。
    2. GameFlow.cs读 EnterBattle 与 FlowState.OnEnter / OnExit，辨认请求接受、场景到位和业务域开始的时机。
    3. BattleLogic.cs读 ClickBoard 与 OnFixedTick，各找一次输入与时间怎样交给远征服务。
    4. IBattleService.cs扫一遍接口的查询、命令和失败原因，再跳具体实现。
    5. BattleService.Damage.cs沿 DamagePiece 找到 ResolveDamage，标出预估、提交和发事件发生的位置。

    GUIDE / 05

    大厅到远征的场景交接

    1. 同一场景切页HomePanel 经 GameFlow.OpenLevels 打开选关，StartScene 仍然在场。
    2. 受理进入章节LevelSelectPanel 把章节交给 EnterBattle。返回 true 代表请求已接受，随后开始异步过场。
    3. 先铺资源再建局SwitchSceneAsync 用 LoadingPanel 遮挡，预载图集与预制体，RevScene 加载 GameScene，预热池并通过 FSM 交割到战斗域。先 BeginCampaign 建首回合，再启动 BattleLogic。
    4. 等实际可画后撤遮挡GamePresentation.WaitUntilReadyAsync 等背景、81 格、手牌和面板到位。测试同时核对 IsTransitioning、Screen 与 RevScene.CurrentName。

    从回合结算读到章节演出

    先在 BattleService 找 EndBattle，看它怎样进入 Settle 并发阶段事件。BattlePresentation 根据阶段切面板。玩家点继续或选奖励，经 BattleLogic 调 ContinueRound / ChooseReward。

    Boss 的入场看 GameFlow.BossIntro。击败后看 GameFlow.BossVictory 如何消费已提交的击败事实并安排登退场、积分与剧情。先分清服务结算结束和演出结束，再判断哪个时机应该回大厅或显示奖励。

    按目录定位当前工程

    目录先看什么

    GUIDE / 11

    新手容易卡住的七个地方

    现象继续查哪里
    只跳到 BattleService 的一个文件按方法名搜索。各个 partial 共享同一个实例和字段，目录表达职责。
    血量变化但 UI 没刷先核对服务伤害回执，再追 PieceHpChanged 的事件订阅、owner 和面板刷新时机。
    按钮方法很短顺调用走到 Logic 或 Service。OnBindView 装配，OnRefreshView 落屏，按钮转发。
    服务从何而来从 GetRequired 回到 Bootstrap 的同类型注册，核对实例由谁创建和注销。
    改表后数据没变核对导表产物、运行时读取的逻辑路径及 PC / Android 包版本。
    两个 AI 目录有相似类型Battle/AI 放状态与决策，Services/Battle/AI 放宿主接线与规则提交。
    决斗既有快照又有检查点快照供显示；检查点含完整原生状态，用于下一帧恢复和预测重演。

    跟一手九路围棋和一条 Agent 建议

    1. 找入口与状态所有者从 PvpPanel 到 PvpService.Submit。进入 SubmitActor 看当前能否操作、如何从棋钟得到用时、怎样在 GoCore.Clone 上预检。
    2. 先看棋规，再看网络到 GoCore.TryApply 跟一手落子、提子或劫，找棋面 StateHash 和 Sequence。回服务看 ApplyMove、TryPrepareMove 怎样核对棋面与时钟后提交。Server 模式先发送 GoRelayCommand，等服务端状态；LAN 将同一手发给对端后本地应用。
    3. 顺着当前连接继续读Fantasy 看 FantasyGoTransport 和 GoBattleHandlers。LAN 看 LanPeerTransport。连接、房间、棋面应用有不同的失败原因，断点先放在当前模式的分支。
    4. 跟代走与只读建议各一次PvpService.Computer 计算本地人机动作。PvpService.Agent 使用 GoAgentPosition 构造候选，回包通过棋局身份与合法性核对后也走 SubmitActor。PvpService.Analysis 则给 胜率与落点提示 提供只读结果。
    5. 读结束点从 GoCore 的自动计分路径查 68 手落子上限，再到 PvpBoardView.Scoring 看逐格计分如何消费已确定结果。正式决斗从 ChallengeDuel 进入，由达到手数与分差门槛的劣势席发起。

    GUIDE / 16

    预测、录像与重连的三个读码练习

    按跳时本机已离地，为什么确认高度仍为 0？
    1. 打开 DuelPrediction.cs。先看 RecordSent 如何记录序号，再看 Rebase 如何在本端已执行同号权威帧之后清理已确认输入。记下仍待恢复期的招式序号和截止帧。
    2. 沿 TrySample → Rebuild 看沙盒如何恢复检查点，重演最多四步。找输出结构 DuelPredictedMotion，对照 PvpDuelView.PaintLocalMotion 读取的位置、高度和方向。
    3. 在 PvpService.Duel.cs 看 RebaseDuelPrediction、TrySampleDuelMotion 的启停门槛。把同一时刻的沙盒高度与确认高度、确认帧号、指纹一起记下。等回包后再对同一帧比较坐标，观察小偏移的 85 ms 纠正。
    两个客户端终局画面差不多，怎样确认逻辑相同？
    1. 用 DuelAuthority.AcceptHashSample 看每 40 帧及终局的样本规则。先查两端帧号、决斗 ID 与版本，再比较该帧的 Hash。两席都通过的上界是 hashMatchedFrame，分歧入口记 hashMismatchFrame。
    2. 打开 DuelReplay.cs 的 ReplayInto，跟从检查点后按顺序 Append 权威历史、逐帧比对指纹和命中字段的过程。第一处不同要回看该帧输入和前一帧状态。
    3. 打开 DuelCheckpoint.cpp。拿保存的垂直速度和 RNG 状态与 DuelSnapshot 对照。用完整检查点恢复才能接着算一帧，读位置和血量只够画一张图。
    回包成批到达或一席掉线，先查什么？
    1. 查服务端的就绪掩码和权威 Frame。一席已就绪但暂时无新输入，权威仍按节拍封帧。连接已断开时查 DisconnectNetworkSeat 是否撤掉该席 Ready 与清理未封口输入。
    2. 查客户端请求的 afterFrame 与回复中的同名字段。例子中本端到 102，收到从 104 起的段时继续请求 102 之后的连续历史。补齐 103 后才会执行 104。先核对这个游标，再检查画面播放头。
    3. Fantasy 复连后回到原决斗，需要重新 Ready 和补齐连续历史。预测等待同帧的新回执再定锚。LAN 直连的宿主由黑方持有。互动帧缺口示意

    要改摇杆、多指或圆键，先读 DuelMoveStick、DuelPressButton 和 GamePvpBuild.DuelHud。要改绯焰或鸦鸦的动作素材，读 DuelEmber 与 DuelYaya。要改实际出招距离，回到 同源规则配置。
