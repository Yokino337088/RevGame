RevCLI 已经能创建 Prefab，为什么还要写项目 Editor 代码？

RevCLI 可以完成通用的 Unity 编辑操作。 RevGame 的 Editor 脚本把资源选择、节点绑定、构建顺序和验收规则固化成可重复的项目配方。此次确实发现了通用的 Sprite Atlas V2 成员操作缺口，已在 Revolution 补齐并同步到 RevGame。

139 个文件均在 Assets/Editor/RevGame 下。按文件名做粗分，含 Build/Builder 的有 42 个，Automation 29 个，Check/Benchmark 47 个，Preview 7 个，其余 14 个。这个统计包含局部类的分文件，只用于说明目录结构。框架自己的 Unity 桥位于 Assets/Revolution/Editor/RevAutomation。

命令从 Python 客户端发到 Unity 桥，由编辑器调用 AssetDatabase、PrefabUtility 等接口。项目也能用 RevAutomationAction 把一套固定配方注册进同一份目录。这样同一个 RevCLI 既能执行通用编辑，也能运行项目配方。

本次增强 Sprite Atlas V2

  • atlas.inspect 读取图集 GUID、成员、Variant 和 Include In Build。
  • atlas.create 使用已导入为 Sprite 的纹理资产创建新 V2 图集，已有目标会被拒绝。
  • atlas.set-packables 使用完整纹理列表替换现有主图集成员，需全局 --confirm。保存前检查所有成员，列表相同直接返回，保留 GUID 与 Importer 设置。空列表表示清空。

这三个动作随 Unity 桥和 CLI 清单一起同步。写入只针对已启用 V2 的工程，成员参数为整张纹理的资产路径。本次范围是 V2 主图集成员，V1 迁移、Variant 和切片级编辑仍由 Unity 或各自工具负责。生产分组、压缩、AB 标记和运行时加载继续由原项目链负责。

  4. 拒绝与收尾。 重复成员、已有目标、缺少确认和不存在的纹理都被拒绝。校验目标文件哈希和无副作用，删除临时资产，核对正式图集、原场景和选择，图集回归无新增 Console 错误。
