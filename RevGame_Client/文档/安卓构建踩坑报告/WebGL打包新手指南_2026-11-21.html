01 · Build 里的四个文件

打开仓库里的 RevGame_Client/Publish/Web/Build。Web 是这次的构建名。遇到 .br，先看前面的后缀来认内容。.br 只表示文件用 Brotli 压小了，好让浏览器少下载一些字节。

RevGame 本地构建文件与磁盘大小
文件它做什么
Web.loader.js
20.19 KiB		启动游戏。网页先执行这个 JavaScript，再用它提供的 createUnityInstance 创建 Unity 游戏实例。它负责找齐启动需要的文件并回报加载进度。

02 · C# 的 DLL 去了哪

Unity 先做出来，再拿去继续编译

你写下的 .cs 是源码。Unity 的 C# 编译器会把一组脚本编成一个托管程序集，通常用 .dll 保存。里面有 IL（中间指令，可以理解成还要再翻译一次的代码），也有类名、方法名等描述信息。比如在 RevGame 本机的 Unity 工程缓存 Library/ScriptAssemblies/ 里，就能找到 RevGame.Rules.dll。

构建电脑上的顺序
C# 源码 → 托管 DLL（IL） → IL2CPP 转成 C++ → 编译为 Web.wasm → Brotli 压成 Web.wasm.br

正式出包时，Unity 会按设置裁掉一部分用不到的代码。IL2CPP 把留下的 IL 转成 C++，Unity 再用编辑器附带的 Emscripten 工具链，把这些代码编译成网页要用的 Wasm。出包时就做完这段翻译叫 AOT（提前编译）。玩家打开网页时，浏览器负责把拿到的 Wasm 变成设备能执行的指令。Unity 的 IL2CPP 编译流程 · WebAssembly 说明

为什么解开 data 后，还是能看到 DLL 的名字

这份 Web.data.br 解开后，里面的 ScriptingAssemblies.json 确实写着 RevGame.Rules.dll。那一项记录的是程序集的名字。同一个数据包里的 Il2CppData/Metadata/global-metadata.dat 保存了类型、方法等描述信息，给引擎运行时使用。方法里真正做事的指令已经编进 Wasm。想找尚未转换的 DLL，可以去看构建电脑上的中间产物。

03 · Mono、IL2CPP、CoreCLR 差在哪

先分清两个问题。目标平台决定游戏在哪儿跑，比如 Windows、Android 或浏览器。脚本后端决定 C# 编出来的代码怎么执行。选了 WebGL 目标，RevGame 这版 Unity 会走 IL2CPP。换成 Windows 也可以用 IL2CPP，只是最后编给 Windows 跑。

用同一段 C# 游戏逻辑对照
运行方式什么时候翻译代码你一般会看到什么
Unity Mono
以 Windows 为例		游戏启动后，随包提供的 Mono 运行时读入 IL，在需要执行时把对应代码翻成本机指令。这叫 JIT（即时编译）。游戏的 .exe 和数据目录。游戏名_Data/Managed/ 里通常能直接找到托管 DLL。
Unity IL2CPP
Windows / Android		Unity 出包时做 AOT，把 IL 转成 C++，再编成相应平台的本机代码。Windows 常见 GameAssembly.dll。Android 则能在 APK 内看到 libil2cpp.so。这两种文件里都是编好的本机代码。
Unity IL2CPP
WebGL		同样先做 AOT，最后编成浏览器能执行的 Wasm。网页入口 index.html，以及本指南看到的 Wasm、JavaScript 和启动数据。
CoreCLR
以常见 .NET 桌面、服务端应用为例		CoreCLR 是现代 .NET 的运行时。这类应用通常也是启动后加载 IL，再由 JIT 编成本机指令。普通目录发布时，常能看到应用和依赖的托管 DLL。选单文件发布时，也能把它们收进同一个可执行文件。

看到 .dll 先看里面装的是什么。 RevGame.Rules.dll 是 C# 编译后带 IL 的程序集。Windows IL2CPP 包里的 GameAssembly.dll 则是给 Windows 加载的本机代码。它们碰巧用了同一个后缀。

RevGame 使用的 Unity 2022.3 提供 Mono 和 IL2CPP 两种脚本后端，具体能选哪种由目标平台决定。Unity 6.7 Beta 的文档把 CoreCLR 列为桌面实验后端。表里的 CoreCLR 行用的是普通 .NET 应用的交付例子。Unity 2022.3 脚本后端 · Windows IL2CPP 产物 · Android IL2CPP 库 · Unity 6.7 的 CoreCLR 后端 · .NET 发布方式

04 · 为什么网页版长得不一样

打开网页后，是浏览器接手启动

  1. 浏览器先拿到 index.html。页面准备好一块画游戏的区域 <canvas>，再加载 Build/Web.loader.js。
  2. 加载器按页面给的地址准备 JavaScript、Wasm 和启动数据。浏览器按服务器提供的响应头解开 Brotli 文件。下载和编译可以重叠，等启动所需的东西就绪后再进入游戏。
  3. Unity 在浏览器里启动，RevGame 的资源系统还会从 StreamingAssets/WebGL/ 加载项目所需的 AB。首次进大厅所需资源和后续玩法资源，可以在不同时间发起请求。

Windows 双击 .exe 时，由操作系统启动游戏。安卓玩家打开的是已经安装的应用。网页玩家打开的是一个网址，由浏览器按地址取文件。这份包交给浏览器执行的是 JavaScript 和 Wasm，启动数据则单独下载给 Unity 使用。

Wasm 算落子，WebGL 画棋子

Unity 把这个网页构建目标叫 WebGL。WebGL 本身是浏览器提供的画图接口。点击棋盘时，Wasm 里的游戏逻辑会判断这一手是否能下。Unity 再通过 WebGL 把新的棋盘画到网页的 canvas 上。WebGL 绘图接口说明

网页游戏还要通过浏览器提供的接口访问网络、声音和本地存储。以项目里的 C++ 决斗内核为例，Windows 版可以载入本机动态库，网页版会把同一份 C++ 源码编成 WebGL 用的 libRevGameCore.a，再把需要的代码链接到 Wasm 里。RevGame 原生插件复盘 · Unity WebGL 原生插件

05 · 怎么出包、怎么打开、卡了看哪里

  1. 出一个网页包。先在 Unity Hub 给对应编辑器安装 WebGL Build Support，再去 Unity 的 File → Build Settings 切到 WebGL。RevGame 还需要先为 WebGL 打好项目 AB。想在本机快速验证，可以用 Build And Run。RevGame 出包流程
  2. 打开这份现成的包。双击 RevGame_Client/Publish/Web/启动网页游戏.cmd，它会开一个本机网页服务，并打开 http://127.0.0.1:17890/。直接双击游戏的 index.html 时，地址会以 file:// 开头，浏览器对这种页面读取其他文件有限制。
  3. 发到网上。把完整网页产物放到能访问的 HTTPS 站点上。RevGame 的 GitHub Pages 发布脚本会先解开预压缩文件，再更新页面里的引用，所以看到 Web.wasm 也可能是同一份程序。本项目 GitHub Pages 实战指南
按 F12 打开开发者工具的 Network（网络），刷新页面看每个请求
你看到的现象先查哪里
页面提示 Web.data.br 下载失败先看地址是不是 file://。换成本机启动器或 HTTPS 后，再看该文件的请求路径和状态码。404 通常表示地址指向的位置没有这个文件。
请求回了 200，游戏却报 Wasm 或解压错看服务器实际发回的内容。发 Brotli 文件时，响应头应有 Content-Encoding: br。Wasm 的类型用 Content-Type: application/wasm，JS 用 application/javascript。有些站点找不到文件时会回一页 HTML，也可能显示 200。
能打开页面，进大厅却一直等资源继续看 StreamingAssets/WebGL/ 的请求。确认网页引用与实际资源目录对应，Player 和 AB 都是同一批发布用的 WebGL 产物。
改了 C#，网页还在用旧逻辑用新代码重新构建 WebGL Player，把新版入口和 Build/ 一起更新，然后刷新核对浏览器请求到的版本。

可以点开 Web.wasm.br 的请求，在 Headers（标头）里核对响应头。Unity 2022.3 的压缩、MIME 与部署说明
