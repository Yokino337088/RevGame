01 · 从 Unity WebGL 包开始

已有 Web 包时，从包目录生成发布版

RevGame 的本机产物位于 RevGame_Client/Publish/Web，包含 index.html、Build 和 StreamingAssets/WebGL。有模板静态文件时还包含 TemplateData。先确认主包 StreamingAssets/WebGL/WebGL 与 BuildManifest.json 位于同一版。

原包由本机 PowerShell 启动器提供 Content-Encoding: br。上传到静态站时，依赖 Brotli 的 Unity 产物需要匹配的 HTTP 响应头。本项目发布工具先在本地解开 .br，同时把入口的引用改成 Web.data、Web.framework.js、Web.wasm。浏览器收到可直接解析的文件，静态站可自行协商传输压缩。Unity WebGL 部署说明

New-Item -ItemType Directory -Force .codex/work | Out-Null
node tools/WebGLPreview/prepare-github-pages.mjs `
  "RevGame_Client/Publish/Web" ".codex/work/web-pages-ready"

这是从 RevGame 仓库根执行的命令。目标使用新的空目录，输入可替换为本次已经验收的 Web 暂存包。脚本读取 HTML 中的实际构建名，所以通常无需改脚本来适配 Unity 的文件名。

更新版脚本还会把每个启动文件的内容摘要写到 URL 的 ?v= 参数。旧版与新版使用不同的缓存键，避免把旧脚本与新 Wasm 混在一起。

Unity 源码或 AB 更新后重新出包

用 Revolution RevCLI 读取当前编辑态和活动目标。切到 WebGL，等导入和明确的重编译结果，再为 WebGL 目标构建、检查映射并发布 AB。向暂存目录构建 IL2CPP Release，记录原工单 ID 等到 BuildReport 成功。按本次约定恢复 Windows 目标。若只更换网页发布格式，直接使用已有完整包。

$unityProject = "RevGame_Client/UnityProject/RevGame.Unity"
$rev = "RevGame_Client/UnityProject/Revolution.RevCLI/rev.py"
py -3.13 $rev --project $unityProject build target --target WebGL
py -3.13 $rev --project $unityProject editor wait
py -3.13 $rev --project $unityProject ab build-incremental --target WebGL
py -3.13 $rev --project $unityProject ab check-map --target WebGL
py -3.13 $rev --project $unityProject ab publish-incremental --target WebGL
py -3.13 $rev --project $unityProject build player --target WebGL --backend il2cpp `
  --path "D:\构建暂存\Web" --detach
py -3.13 $rev --project $unityProject --timeout 3700 job <工单ID> --wait

代码更新后的完整复编顺序与 UTF-8 工具链问题见同目录的构建复盘。WebGL 构建踩坑复盘

平台切换提交后如果查询原工单得到 JobNotFound，先用 build settings 回读活动目标，并等编辑器完成编译。活动目标已正确时，从导入和复编步骤继续。

03 · 首次上线

  1. 在准备好的静态目录初始化独立的 gh-pages 分支。提交入口、构建文件、WebGL AB 和 .nojekyll，然后推送到目标仓库。
  2. 在仓库 Settings → Pages 打开 Build and deployment。Source 选 Deploy from a branch，分支选 gh-pages，目录选 / (root)，保存。
  3. 等待 Pages 构建状态为 built。浏览器直接访问 GitHub 给出的地址，确认页面与资源加载。
  4. 把同一个 HTTPS 地址写入 README.md，再提交到主分支。仓库 About 可填这个网址。
$readySite = ".codex/work/web-pages-ready"
git -C $readySite init -b gh-pages
git -C $readySite remote add origin https://github.com/Yokino337088/RevGame.git
git -C $readySite add -A
git -C $readySite commit -m "发布围棋大作战 WebGL"
git -C $readySite push -u origin gh-pages

RevGame 首次发布用同一套分支配置，由 GitHub Pages API 设置发布来源。管理员也可以用上述界面操作。配置 GitHub Pages 发布来源

04 · 更新已经上线的版本

在另一个工作树从远端 gh-pages 起步，替换入口和启动文件后快进推送。源代码工作区用于开发。版本化 AB 目录按内容新增，同一版沿用原目录。上一版已打开的页面仍能读取它自己的 AB 地址。

$readySite = (Resolve-Path ".codex/work/web-pages-ready").Path
$siteTree = ".codex/work/revgame-live-pages"
git fetch origin gh-pages
git worktree add --detach $siteTree origin/gh-pages
git -C $siteTree rm -r --ignore-unmatch -- .nojekyll index.html Build TemplateData
foreach ($name in @(".nojekyll","index.html","Build","StreamingAssets","TemplateData")) {
  $source = Join-Path $readySite $name
  if (Test-Path -LiteralPath $source) {
    Copy-Item -LiteralPath $source -Destination $siteTree -Recurse -Force
  }
}
git -C $siteTree add -A
git -C $siteTree diff --cached --stat
git -C $siteTree commit -m "更新围棋大作战网页试玩版"
git -C $siteTree push origin HEAD:refs/heads/gh-pages

每次构建使用新的工作树目录，已有工作树可在确认干净后快进到最新发布分支。遇到远端更新时，先取回并核对差异，再基于远端新提交发布。

本次更新时，常规推送出现 unexpected disconnect while reading sideband packet，低速超时后的远端引用仍停在旧提交。先回读 git ls-remote origin refs/heads/gh-pages。在这次代理连接里，原有提交改用下面的一次性 HTTP 参数成功推送。HTTP 日志确认请求携带 Content-Length 并收到 HTTP 200。Git HTTP 配置说明

git -C $siteTree -c http.version=HTTP/1.1 -c http.postBuffer=67108864 `
  -c "http.extraHeader=Expect:" -c http.lowSpeedLimit=2048 -c http.lowSpeedTime=75 `
  push --progress origin HEAD:refs/heads/gh-pages

05 · 验收和常见故障

现象核对顺序
双击页面报 file://本机用 启动网页游戏.cmd 起 HTTP，公开版使用 HTTPS 入口。
.br 下载成功但 Loader 解码失败核对实际响应头和入口引用。如果使用本项目的转换输出，三个启动文件已解包。
404 或返回的是 HTML查 Pages 发布分支、项目子路径与大小写。核对 Wasm 响应是 application/wasm，再查平台主包及业务 AB。
换包后读到前一版文件按同一轮提交替换整个发布集合。在 Network 查缓存与实际响应，核对新部署状态和资源哈希后再验。
Node 读取清单报 JSON 首字符非法Windows 上 Unity 写出的 BuildManifest.json 可能带 UTF-8 BOM。转换脚本在解析前移除开头的 BOM。
分支推送拒绝大文件按单文件和整站两种口径验体积。超出 Git 单文件限制时改用 Pages 的 Actions 发布产物或其它支持的大文件交付方式。

实际验收用未登录浏览器。从 README 打开网页即进入大厅，再用「开始闯关」确认按钮和业务资源。在 Network 核对入口、Loader、Wasm、Data 和本版平台主包。首次上线的正式产物为 259 个文件，163,570,222 字节，最大文件 Web.wasm 为 48,240,699 字节。首次 Pages 发布 · GitHub 仓库限制

633c23d 发布时验证了内容摘要 URL、Wasm MIME 与浏览器关闭由试玩页面打开的标签页。当前直进模式下，浏览器保留普通标签页时会显示「已退出游戏」，退出前的 Player 随导航清理。早期退出发布提交
