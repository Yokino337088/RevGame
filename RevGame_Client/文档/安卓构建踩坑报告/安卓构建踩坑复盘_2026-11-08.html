01 · 构建与签名

非 ASCII 项目路径阻断 Unity Android 工具

Unity 日志明确报 Project path … contains non-ASCII characters。把最终 APK 改到英文目录无法解决 Unity 读取源项目时的检查。实际在纯 ASCII 的独立工程同步 Assets、Packages、ProjectSettings 与目标 AB，原项目继续用 live 编辑，Gradle/Bee/IL2CPP 中间产物留在构建副本，验证后才把 APK 复制回 RevGame/Android。

复用副本时，增量复制会留下源工程已移除的文件。宽屏复包前归档旧导出及残留 RevGameActivity.java、对应 meta 和 PC AB。核对 SDK、NDK、JDK 与导出后的 local.properties 实际指向；构建副本的路径校验先于任何移动或清理。

旧 D8 读取 API 35 的 android.jar 崩溃

搬到 ASCII 路径后又遇到 :launcher:desugarDebugFileDependencies，具体错误为 API 35 的 android.jar 触发 D8 NullPointerException。临时 Mono 测试工程在 Unity 导出后按 API 32 组包，Gradle 复跑通过。这个组合只用于当时的开发测试。Release 仍按 API 35 单独导出和验包。

Release 迁移需要同时核对 AGP、Java 和 NDK

当天正式链路为 Unity 2022.3.15f1c1、IL2CPP ARM64、JDK 17、Gradle 8.9、AGP 8.7.3、compile/target SDK 35。适配集中在导出的 Gradle 工程，包括两模块 namespace、清理旧 manifest package 声明、Java UTF-8、依赖仓库、移除 debug signingConfig 和本地 SDK 路径。

CXX1100 后跟的 NDK is not installed 实际是 AGP 期望 NDK 27.0.12077973，配置路径指向 Unity 的 23.1.7779620。两模块显式对齐 ndkVersion 和 ndkPath 后通过。依赖预热之后才用 offline，Gradle 与 IL2CPP 分别限制并发。首次修正后的 Gradle 用时 27m55s，宽屏复包在同链路复用可重建 IL2CPP 缓存后用时 3m36s。这两次包含的编译工作量不同。

后端、ABI、签名和版本号各自验收

Mono 开发测试包是 ARMv7。正式包使用 IL2CPP ARM64，同时核对 libRevGameCore.so 的 PluginImporter CPU 与 APK 中实际 arm64-v8a 产物。签名前做 zipalign，签后用 apksigner verify --print-certs 比对上一版证书，用 aapt dump badging 检查包名、版本、SDK、ABI 和启动 Activity。宽屏包 1.0.1 / versionCode 2、同包名及同签名已核对。私钥、口令和 APK 都留在交付环境。Android apksigner

ARM64 与 16 KB 页兼容分开。当天记录的 ELF LOAD 对齐中，自研库为 16384，Unity、IL2CPP、Burst 和 libmain 为 4096。当前记录只能证明包内 ABI；16 KB 兼容还需要逐库 ELF、APK ZIP 对齐与 16 KB 环境启动验证。Android 16 KB 页尺寸指南

02 · AB、包体和资源质量

从源工程构建目标 AB，副本和 APK 都查串包

用项目 game.background.build 生成并发布目标 AB，核对主包、BuildManifest.json、映射与依赖。Android 构建副本屏蔽 Assets/StreamingAssets/PC 及残留 meta，Gradle 导出后再次确认。宽屏 APK 实际验得 167 个 Android 资源文件、0 个 PC 包。两个平台后来各重建 82 个业务 AB，连同主包、清单和清单 JSON 共 167 个发布文件，逐文件校验 SHA-256。

包体减少来自多部分变化

体积净减少约 10.24 MiB，主要来自 Player 数据缩小。宽屏签名包是 74,379,415 字节。后续画质提升只更新资源库中的 AB，不能用本表推算新 APK 的最终大小。

图集切片、透明度和清晰度一起验

决斗序列帧要保持原有动作、帧名、切片、播放顺序和引用，生成 Sprite Atlas V2 后观察真实动画换帧。仅在 Project 窗口看到 Sprite 子资产无法证明 Player 已用到打包图集。关键图集和帧资产按用途分组，避免所有帧常驻。

鸦鸦 10 张表情原图为 1600×2400。导入上限由 1024 提到 2048，切片约由 683×1024 变成 1365×2044。源图直读，最终图集才做一次有损压缩，PC 用 BC7，Android 用 ASTC 6×6，剧情与战斗分包。两套合计由约 1.9 MiB 增至 Android 6.6 MiB、PC 12.8 MiB。用实际保留像素报告提升，并把 AB 大小和真机显存分开测。

剧情源文件在打包中更新，第二个平台的字库门禁拒绝继续

Android 首轮构建后，PC 校验发现 StoryBook 在打包期间再次保存。重新读取最新版并核对 Excel 仍是已导出的版本，重建字库后按相同输入哈希构建两端。保留源 Excel、生成文本、字体和字体清单的配套关系。Git 验证按已暂存源码生成清单，工作区的换行与未提交内容可能使本地字库输入哈希不同。

03 · 横屏、黑边和手机 UI

分离设计画幅、原生窗口、安全区与棋盘占位

固定 16:9 原生壳在宽屏会留下左右黑边，直接把 16:9 内容拉到全宽又会让人物和棋格变形。RevGame 保留 1920×1080 设计坐标，运行窗口按真实设备画幅，背景等比 cover。宽屏包验得可调整大小的 UnityPlayerActivity，移除旧固定比例壳。交互内容由 GameBattleLayout 与 GameMobileLayout 按安全区和棋盘实际投影定位。原生窗口、相机背景和 UI 锚点各验一遍。Unity Screen.safeArea

手机横向多出来的空间优先给两侧，棋盘维持比例

同一个 1920×1080 设计坐标在 Game 窗口和 Device Simulator 上可以对应不同的安全画幅。用预制体锚点、CanvasScaler 和原始偏移映射，窗口或安全区改变时重新计算，避免把上一次偏移继续叠加。保留棋盘位置与比例，远征手牌、无尽备战牌组、九路围棋的 Agent 和结算操作分别约束在棋盘外。验边界、交叠和真实点击。

当天盘点 21 个 RevUI 面板加独立决斗 HUD。Huawei P40 Pro 的 Unity Device Simulator 等宽屏预览覆盖剧情与多个玩法，普通 Game 用于 16:9 对照。清单数量表示布局分类范围，不能当作逐页真机点按数量。

无尽鸦鸦立绘大小和对白排序是两个问题

用可见视口比例定义立绘高度，最终移动端目标为 50%。对白使用独立覆盖 Canvas，排序 200，使敌方棋子无法遮住文本。检查触发、配置、表情租约、对白内容完整性和重叠，再核对真实画面。早期无尽断言曾失败，后来分开重跑入场和互动，50% 高度与对白排序有预览断言。

04 · 装得上之后的故障

Android 目标 Play 启动时大厅鸦鸦没有可画 Sprite

控制器接上和 Renderer 已有可绘制帧是两回事。大厅借用 YayaIdle24，重绑 Animator 并采样待机首帧，再检查 Sprite 和实际换帧。Android 目标在编辑器直读及 AB 模式均验过大厅显示和帧推进；这只覆盖大厅，不能代表棋盘材质和全部图形路径。

前六章与无尽互动缺失

排查顺序是实际触发条件、配置表、表情图集、显示面积、占位冲突、对白排序。Android 目标直读有六章逐章记录，无尽在后续移动预览单独复验。正式 APK 中自然触发的频率、弱设备表现与排序仍需真机记录。

Windows Editor 载入 Android AB 的棋盘 Shader 不可用

第一章棋盘材质请求返回资源错误 None，但宿主对其 Shader 判定不可用，首章场景屏障因此拒绝进场。Android 目标只说明本次使用目标 AB 和编译条件，宿主仍是 Windows Editor。保留原始失败，用 Android 直读验证业务、PC 真 AB 验证资源交接，实际 Android 图形兼容由目标设备验。

第一章 Boss 领奖卡在第二章剧情，PC 也复现

准备事件同时通知剧情和场景背景。命中缓存的剧情先拿到旧章 Ready，尝试为第二章借用第一章背景，出现「剧情背景与当前章节未交付：2」。修复后让事件完成交接，等到场景背景就绪并核对目标章号再开剧情。背景真正失败时沿用已有返回入口。PC 真 AB 做了修复前后对照，Android 目标直读用同一领奖路径验证了剧情、棋盘和下一次落子。章间交接修复

DeepSeek Key 保存曾误用 Windows 凭据保护

Windows DPAPI 在 Android 不可用。项目按实际运行平台分流，Android 在 Application.persistentDataPath 写入用户授权的明文 DeepSeekAgentSettings.txt，同目录临时写入后再替换。Windows 保留 DPAPI，Device Simulator 的手机标志只用于布局。用假 Key 和隔离槽跨 Play 验证写入、读回和清除。报告与 Git 均不得带 Key、用户配置或签名凭据。Android 凭据与宽屏修复

决斗本地联机入口与测试地址

开发包的服务器默认值使用当时电脑的局域网地址和 20000 端口。换电脑或网段要核对新地址、监听端口和可达性。构建、按钮显示、触屏命中、原生战斗推进和两设备帧哈希是不同层的验收。预览和 APK 文件检查无法证明真实 Android 局域网对局同步。

Unity 崩溃、重载与旧工单标记

一次原生崩溃出现在编辑器 Play 预热附近，日志保留了最后的资源池和 RevTask 调用。该堆栈不足以定出原生根因。重连并重新完成相关 Play 流程后记录通过与仍未复验的项目。另一次 HTTP 模式下 build.target 仍写 jobs/<id>/target-started，目录不存在而失败。用临时项目编辑器动作异步切换并读回目标，复测后删除动作、恢复 Android，继续通过 HTTP 通信。

06 · 下次按此顺序

  1. 确定测试或 Release、目标 ABI、SDK、项目版本、已有签名身份及输出位置。
  2. 核对源版本、导表和字库，按目标发布 AB，再用 ASCII 副本隔离构建。排除 PC AB 与残留 Activity。
  3. 先核对 Unity 导出 BuildReport，再核对 Gradle 错误中的首个失败任务。比对 JDK、AGP、Gradle、SDK、NDK 实际值。
  4. 核对包体分项、切片、图集、SHA-256、ELF 与合并 Manifest。对齐后签名，验证签名和更新身份再交付。
  5. 普通 Game 与异形宽屏模拟对照。背景全屏、内容安全、控件避棋盘，并验证真实点击。
  6. 隔离 Play 走正式流程，用 RevMCP 的 rev_discover、rev_call 与 rev_run 保留动作、断言、截图和 finally 清理。
  7. 真机用实际 APK 验证冷启动、两侧画幅、系统栏和点击、决斗原生插件、凭据存取、Boss 领奖到下一章。有 16 KB 目标时单独验环境和所有原生库。
  8. 按构建、验包、编辑器直读、目标 AB 和真机记录结论，恢复 Unity 与原目标。仓库只提交源码、文档和约定内资源。
