01 · 浏览器打开方式与全屏

双击 HTML 时，Unity 加载器请求 Web.data.br 失败

截图同时出现 Failed to download file Build/Web.data.br 和 file://。双击 index.html 会以文件协议打开页面，浏览器拦截了 Unity 加载器的资源读取。报错发生在 Wasm 和游戏代码启动前。即使 Web.data.br 在磁盘上，也需要通过受支持的网页服务加载。Unity 2022.3 WebGL 部署

本机双击 Publish/Web/启动网页游戏.cmd。启动器在回环地址提供 HTTP 服务并打开游戏页。直接打开 HTML 时，RevGame 模板现在会在发出 Unity 下载请求前显示启动说明。线上将完整交付目录部署到 HTTPS。

部署时检查压缩资源的实际响应。*.br 需要 Content-Encoding: br，*.wasm.br 需要 Content-Type: application/wasm，JavaScript 文件要有对应类型。通过 Network 同时看状态码和响应体，静态站回退到 HTML 的 200 响应同样会导致解码失败。有独立 CDN 时还要核对 CORS。Unity 压缩与服务器响应头

页面铺满与浏览器原生全屏

网页模板把画布铺满视口。Windows 本机启动器可用 Edge 或 Chrome 的启动参数打开全屏窗口。普通网页在玩家第一次点击时申请原生全屏，退出或请求被拒绝时保留按钮。全屏请求受浏览器的用户激活和嵌入权限控制，首次请求需要留在真实手势回调内。Fullscreen 标准

02 · 平台切换、Emscripten 和工单

内存工单访问了不存在的 target-started

build.target 通过 HTTP 内存模式提交时抛出 DirectoryNotFoundException，路径指向 Library/RevolutionAutomation/jobs/<id>/target-started。动作拿磁盘工单标记追踪跨域重载，而内存传输没有该目录。Revolution 改用 Editor SessionState 保存原请求身份，切换完成后按同一工单核对目标。本轮构建结束时实际回读到 StandaloneWindows64。

中文 Windows 上，Emscripten 的 Python 按 GBK 读取 LLVM 输出

首次构建在 llvm-nm --print-file-name 后报 UnicodeDecodeError: 'gbk' codec can't decode byte 0x80，后续出现 IndexError。用 Unity 自带 Python 复查，默认编码为 cp936，设置 PYTHONUTF8=1 后为 UTF-8。以 UTF-8 环境启动 Editor 后，原有中文路径下的 WebGL 构建成功。框架也在 Windows WebGL 构建动作内部设置该环境变量，并在结束时恢复原值。

客户端等超时后，Unity 仍能成功写完包

一次 WebGL Release 超过了客户端等待窗口，原工单最终耗时 2,165.135 秒，BuildReport 成功。长任务提交时使用 --detach，保留工单 ID，再用 job <id> --wait 读取结果。先查接单和实际 BuildReport，再判断是否需要发新工单。

03 · WebGL AB 与正式版功能

Unity 将其它平台的 StreamingAssets 也复制进了网页目录

用 WebGL 目标构建并发布 AB 后，另外检查最终 Player 的 StreamingAssets。Unity 原始目录同时带上 PC 和 Android 资源，大小为 276,056,357 字节。最终从暂存区交付 Build、Web 模板和 WebGL 资源，目录大小为 114,816,045 字节。清单列出的 119 个业务包连同平台主包均做摘要核验。遇到整个旧目录无法移动时，从已校验暂存品逐文件原子替换并保留旧版备份。

WebGL Release 调用的方法被开发宏裁掉

默认开放内容的版本首次打包报 CS1061，大厅调用的 GameFlow.ReplayOpeningStory 与 ReplayTutorial 只在开发配置编译。正式大厅回看和重玩改走保留在 Release 的流程入口，GM 注册继续由开发宏保护。Web Player 的六章、棋子、奖励和故事开放走业务策略，实际通关与领取仍由原来的记录驱动。

浏览器报键位名缺失，输入与音频需要分别验收

旧 RevInput 用同名解析建立键位表。Unity 2022.3 的 KeyCode 对应成员是 Print，Revolution 对外名称是 PrintScreen。显式映射这对兼容名称，已有绑定值和对外命名继续沿用。此前用 Edge 从序章经过教学、进入大厅并开始正式棋局，核对了浏览器的按键和棋盘输入，以及确实播放的 BGM 与操作音。

客户端首次音频播放跟随用户手势。长 BGM 和短音效按目标导入设置检查，分别观察浏览器中的播放进度和声音缓冲。桌面 Editor 把活动构建目标切到 WebGL 时，宿主仍是桌面，应继续走桌面音频能力。Unity 2022.3 WebGL 音频

04 · Revolution WebGL 审计与修复

源码中确认的兼容性问题及对应处理
模块风险修复
资源加载ReleaseAll 后旧 AB 请求仍可能等待并重试，失败难区分 HTTP 问题。请求携带加载代次，退代中止在途请求并停止重试。使用实时时钟检查超时，记录包名、请求结果和 HTTP 状态码。单个消费者由各自作用域释放持有。
文件存档浏览器虚拟文件提交完成后，当前 Unity Player 需要调度 IDBFS 写回。RevFileSave 成功提交持久目录下主档和备份后排队写回。Unity 2022.3 沿用引擎队列，其它宿主能力按插件的串行回退处理。
日志和开发自动化构造文件日志时过早创建系统等待句柄，部分小游戏宏下本机 HTTP 分支仍会编译。能力与目录探测通过后才建文件线程句柄。浏览器和小游戏 Player 跳过本机监听器。
音频平台能力桌面 Editor 选中 WebGL 后被误判为需要浏览器的音频解锁，小游戏宏不完整。按真实运行宿主和各小游戏宏判断，区分 Editor 与实际 Player。
可选热更新部分小游戏名称与平台路径分派不一致。拉清单、内置文本或候选 AB 时缺少网页时限。统一到 WebGL URL 入口，以真实帧检查超时和取消，失败沿用原有重试与版本保护。

06 · 下次按此顺序

  1. 用实际编辑器版本确认 WebGL 模块、构建目标和当前编辑态。切平台后等待导入和重编，记住原开发目标。
  2. 同一目标构建并发布 AB，查平台主包、映射、依赖与摘要。以正式宏编译 WebGL Player，长工单保留原 ID。
  3. 对照 Unity 最终 BuildReport 和输出目录。校验待交付的 Build、网页模板和实际需要的 StreamingAssets。
  4. 本机通过 HTTP 启动，线上通过 HTTPS 部署。定位失败先查 URL 协议和响应头，再查浏览器策略、引擎与业务日志。
  5. 按任务范围验证首次进入、手势全屏和声音、游戏输入、关键场景和存档重开。保留目标环境与实际覆盖记录。
  6. 构建后回读开发目标。框架缺陷回到源仓库修订，以对应正式导出的提交同步工程。
