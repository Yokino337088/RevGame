# 鸦鸦大厅与剧情工程验收 · 2026-11-04

本次把大厅画面归到 StartScene 场景对象：`LobbyScene/MagicCottage` 使用 MeshRenderer，`LobbyScene/Yaya` 使用 SpriteRenderer 和 Animator。HomePanel 只保留菜单；已移除 screenBackground 旧漩涡以及临时 UI 背景/角色。鸦鸦全身落在原画左侧圆台，使用已有 24 帧往返待机。

## 场景、资源与流程

- 小屋 Shader 使用 RGB 遮罩：R 天空轻微日照变化，G 水面微波，B 晶石/药瓶柔光；屋体与站台保持稳定。
- `GamePresentation` 等待大厅材质、图集与动画首帧可画，之后才交付菜单。大厅角色租约归 StartScene，销毁先解除 Renderer/Animator 引用再释放。
- `StoryBook` 保存篇章背景和每句表情编号；新增校验拒绝缺图、重复编号、未知篇章与非法背景。剧情表情与大厅待机分属 YayaExpressions / YayaIdle24 图集。
- StoryBook仍直接引用六张选用表情，所以config_story依赖atlas_yayaexpressions，配置句柄存活时保留该依赖。面板关闭会归还自己的图集绑定租约，但不据此宣称表情纹理已全部卸载；未加载未选用的其它差分。
- 剧情面板覆盖全屏，立绘在左侧且置顶，对话卡放右下，使用已有 UI_ChooseLevel_imgTip2 的九宫格 Sprite；右上跳过走正式 GameFlow 收尾。
- `GameFlow` 仍是唯一流程所有者。进入六章首回合播放本章对白，重开战役重播；开场跳过仍串联教学，不伪造棋盘实操完成。关闭先清 UI 图像引用，再归还表情图集租约。
- 章节剧情借当前 GamePresentation 的实际纹理与 Shader；每次面板只创建一份材质副本以承接 SpriteRenderer 的纹理/UV，不逐帧克隆、不预载六章背景。

## 开发态 GM

| GM | 用法 / 约束 |
|---|---|
| `大厅/场景状态` | 查询 StartScene 场景根、就绪与旧 UI 背景残留 |
| `剧情/篇章清单` | 列出稳定 ID、标题、背景章节与句数 |
| `剧情/重播开场` | 重播正式开场，保留首次进度，不自动串联教学 |
| `剧情/播放篇章 opening` | 仅隔离存档预览；章节背景要求先进入匹配章节 |
| `剧情/下一句` | 和玩家点击共用入口，末句正常完成 |
| `剧情/跳过` | 和右上按钮共用收尾，解除剧情输入锁 |
| `剧情/状态` | 读取篇章、行号、表情、背景、层级、整句排版和拒绝原因 |

GM 在 `GameGmCommands` 中集中登记和注销，生产非开发版本不注册。MCP 参数必须按真实 schema：`剧情/播放篇章` 使用 `{"arg0":"opening"}`，`RevGame/进入战斗` 使用 `{"arg0":1}`。返回 accepted 只代表接受请求，需等 `story.state.transitioning=false` 与 `story.yaya-state.backdropReady=true`。

自动化查询 `story.state` / `story.yaya-state` / `lobby.yaya-state` 无副作用；动作 `story.next` / `story.skip` / `story.preview` 复用正式流程。预览错误 ID、背景不匹配或播放中重复请求会明确拒绝，不启动资源故障面板。
