# 开发属性GM指令说明 · 2026-10-22

在Unity进入Play后，打开菜单 `Revolution.Tools/GM 指令面板`（Ctrl+Shift+G）。以下七条指令已接入项目Bootstrap，人工和官方Revolution.Automation调用同一套实现。

| 指令 | 示例 | 作用 |
| --- | --- | --- |
| 属性设置 | `RevGame/属性设置 250 100 0 0` | 覆盖攻击、攻速、等效防御、最大生命四项额外百分比，重复调用不累计 |
| 加攻击 | `RevGame/加攻击 25` | 当前额外攻击再加25个百分点 |
| 加攻速 | `RevGame/加攻速 100` | 当前额外攻速再加100个百分点 |
| 加防御 | `RevGame/加防御 50` | 当前等效防御额外值再加50个百分点 |
| 加血量 | `RevGame/加血量 100` | 当前最大生命额外值再加100个百分点 |
| 属性查询 | `RevGame/属性查询` | 返回当前四项JSON快照 |
| 属性清除 | `RevGame/属性清除` | 四项归零，撤销开发强化 |

## 数值口径

全部为额外整数百分比，0不加成，+100%=原值×2，+250%=原值×3.5。若想总计250%攻击，应设置攻击参数150。每项最终范围0～10000%，这是防溢出和过量动作的技术边界。累计命令允许负数下调；缺参、非整数、越界和溢出均整体拒绝，原配置保持不变。

攻击在真实普通攻击伤害出口生效，保留整数截断。攻速提高攻击进度积累，不改变整个游戏时钟或敌人移动冷却。游戏没有独立防御属性，所以等效防御+100%为承受正伤害÷2、最少1，护盾挡完的0保持0。生命加成调整最大生命并保留当前生命比例，不是治疗或复活；已有棋、后落手牌、援军和升星都继承，原准备生命增益仍相乘组合。

四项均只作用于开发态玩家棋子，不修改敌方属性、Excel、只读图鉴、存档或正式发行包。手动设置跨本次Play的回合保留；需要恢复普通游玩时执行属性清除或结束Play。

## AI与自动化调用

先通过官方Automation的 `gm.list` 确认运行期注册，再用 `gm.exec` 传入 `{"command":"RevGame/属性设置 250 100 0 0"}`。桥层成功与GM层成功必须同时成立。AI重试优先用“属性设置”，避免累计命令重复加成。

成功返回：

```json
{"attackBonusPercent":250,"attackSpeedBonusPercent":100,"defenseBonusPercent":0,"healthBonusPercent":0}
```

本项目业务计划可插入下列步骤，expected核对精确JSON：

```json
{
  "name": "通过GM设置本轮强化",
  "op": "gm",
  "command": "RevGame/属性设置 250 100 0 0",
  "expected": "{\"attackBonusPercent\":250,\"attackSpeedBonusPercent\":100,\"defenseBonusPercent\":0,\"healthBonusPercent\":0}"
}
```

计划顶层 `boost` 也接受上述四字段；旧计划缺失生命字段时默认0。自动化开始会用计划配置接管手动强化；计划内GM变更沿用自动化owner，完成、失败、取消和退出Play均释放，不恢复旧手动强化。报告boost为最终值，每次调整另记在evidence。七条属性命令已精确加入计划白名单，没有放开任意脚本、跳关、清敌或强制胜利。

实际重跑：

```powershell
python -X utf8 RevGame_Client/Tests/BusinessFlowAutomation/run_flow.py RevGame_Client/Tests/BusinessFlowAutomation/plans/first-chapter-2026-10-22-attack250-speed100.json
```
