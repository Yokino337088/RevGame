# 全体我方守阵攻击与低星棋子反馈遗漏修复

2026-10-19 · RevGame · Unity 2022.3.15f1c1 · Revolution 框架验证项目

## 结论

本次处理两方面问题：**旧攻击规则会让近战因够不到敌人、我方棋子因零气而完全不出手；密集齐射的表现队列又会长期漏掉部分棋子的反馈。** 代码没有“一级棋子不能攻击”的判断，星级不是禁攻条件。

按用户最终要求“棋盘上所有我方棋子都要攻击敌人”，现在**所有存活我方棋子原地守阵参战**：近战先打身体边缘相邻敌人，没有接触目标时援击全盘；远程全盘索敌；我方零气仍可反击。行动仍按原攻击时钟积攒，不会每帧无限攻击。敌方原职业射程及锁死禁攻继续保留。

这既包括可确认的反馈调度 Bug，也包括按最新要求调整旧玩法限制。不能只补弹道就宣称“所有棋子都真实攻击了”，必须同时检查目标查询、出手资格和实际扣血。

## 1. 玩家看到的现象

- 多颗棋子同时攻击时，较早落下的棋子反复出现攻击提示，后落下的一级棋子常常没有文字、弹道或明显动作。
- 远程棋子即使有敌人可以攻击，也可能在画面上像是一直站着不动。
- 旧规则下，近战远离敌人或我方棋子零气时，模型确实会跳过攻击；仅改特效无法让它们参战。

## 2. 攻击是怎样发生的

```text
BattleService.StepSide
  → MoveRules.CanAttack 统一判断攻击资格
  → 积攒攻击行动进度，达到一次出手机会
  → MoveRules.GetAttackTargets 找到合法敌人
  → BattleService.Attack
       ├─ PieceAttacked：告诉表现层“这颗棋子确实出手了”
       └─ DamagePiece：结算真实伤害，发送命中快照
            → BoardView：身体动作、口号、弹道、伤害文字
```

**模型负责战斗结果，视图负责把结果画出来。** 为了控制性能，表现可以限量、合并和丢弃过期信息，但它不能取消真实攻击，也不能在动画结束时再扣一次血。

| 检查点 | 本次发现 | 含义 |
|---|---|---|
| 星级 | 攻击循环没有一级禁攻分支 | 不能把显示不足归咎于星级 |
| 我方远程 | 全盘索敌 | 不需直线或走到邻格；友军不挡住守阵火力 |
| 我方近战 | 身体边缘接触目标优先；没有接触敌人时全盘援击 | 2×2 棋子按整个身体边界查接触；无需自动移动追敌 |
| 我方零气 | 保留 `IsLocked` 状态，但不再禁止出手 | 没有增加气、解除围困或免除原有受击惩罚；未新加输出削弱倍率 |
| 我方移动 | 继续原地守阵；玩家仍可手动调整 | 攻击不拆一眼、两眼阵型 |
| 敌人 | 原职业射程与锁死禁攻保留 | 没有一并获得我方全盘援击和零气反击 |

## 3. 原因：旧规则限制与反馈遗漏叠加

### 旧规则确实会让部分我方停攻

旧 `StepSide` 和目标/射界查询分别检查锁死状态；近战只查询相邻射线，而玩家又不会自动追敌。于是离敌人较远的近战一直没有目标，零气的我方则在行动入口被跳过。这是旧玩法限制，与用户最终“全体我方原地参战”的要求不一致，并非一级特有故障。

### 有数量预算，却没有公平性

旧逻辑已经给表现设置上限，避免弹幕和子弹无限增加。问题出在**哪些请求能留下来**：

1. 攻击口号队列最多接收 12 条；同一个模拟步里按固定棋子遍历顺序入队，队满后后续请求直接放弃。
2. 弹道队列最多 24 条，同样采用先到先占、满额直接放弃。
3. 口号出队后，如果当前文字预算不足，旧实现会继续循环，导致排队请求在还没有显示时就被消耗掉。
4. 齐射反复以相近顺序发生，前排请求持续抢到机会，后排请求持续失败。不是某一帧偶然省略，而可能是同一颗棋子长期没有反馈。

一级棋子经常是后续新落下的棋子，因而更容易暴露这种“固定顺序饥饿”；**一级本身不是触发原因**。

## 4. 修复做了什么

### 统一攻击资格，所有存活我方都能原地参战

新增 `MoveRules.CanAttack(Piece)`，由 `BattleService.StepSide`、`GetAttackTargets`、`GetAttackCoverage` 三处共用。它对我方检查存在且存活，对敌方还要求未锁死。不能只放开战斗入口却让目标查询继续返回空，也不能让长按范围提示与真实攻击互相矛盾。

我方近战先调用现有接触射线查询，有身边敌人就优先攻击；没有接触敌人时，和我方远程一起进入全盘敌人候选。候选按距离优先、编号破同分稳定排列，不修改棋盘占格、不试移真实棋子、不改变行动频率。

**零气反击不是围困免疫。** 气眼、`IsLocked` 和原有被围时的受击代价仍然存在，只移除我方“整颗禁止攻击”的门槛；没有增加我方气、清除状态、另加减伤，亦没有新设输出惩罚。敌方走原来的职业规则与锁死禁攻。

援军落点评分也同步调整：近战援军仍按身体边缘真正接触的敌人数评分，优先贴敌、破眼，不能把新的“全盘可援击目标数”当作贴身敌人数，否则后排空格也会错误拿高分。远程援军继续优先安全后排与我方主体阵营。

### 每次真实攻击都有一个不占飘字预算的身体动作

`BoardView` 收到 `PieceAttacked` 时，先找到本次出手棋子的 `PieceView`，立即触发 `PlayAttackPulse()`：**出手当帧轻压，随后在 0.20 秒内回弹**。横向最大增加 10%，纵向最大压缩 8%，最后恢复 `Awake` 缓存的身体基准缩放。

姿态记录“游戏时间到哪一刻结束”，不在刚启动时扣除出手前一帧的完整 `deltaTime`。这是本轮低帧率 Play 检查发现的边界：若当前帧很长，直接扣整帧时长会让刚出手的动作当场结束。现在先落下立即姿态，再按出手之后的绝对游戏时间回弹。测试也分开检查立即姿态、根节点不变与自然恢复，不假定后台窗口一定能采到第 70 毫秒的中间帧。

这条轻量时间轴复用棋子已有的 `RevMono` 更新，不为每次攻击创建新对象、计时器或 Tween，不移动棋盘占格，也不修改射程和伤害。即使全场文字、弹道名额暂时用完，仍能看见该棋子正在出手。

动作只改身体子节点，不缩放整个棋盘节点。死亡、阶段切换、重新绑定及回池时恢复原始缩放，避免上一颗棋子的动作残留给下一颗复用对象。

**Play 检查还发现一处预制体结构问题：** 实际 `SlimePiece` 预制体的 `bodyRenderer` 原先挂在根节点，而非独立身体子节点。若直接对它回弹，整颗棋子根节点也会缩放，血条和饰件可能跟着变形。此次将原渲染器迁到独立 `Body` 子节点，保留原渲染器 fileID、图片、材质、排序和 `PieceView` 引用，根节点上的六个配件保持原位。

[`GamePieceShaderBuilder.EnsureBodyChild`](../../UnityProject/RevGame.Unity/Assets/Editor/RevGame/GamePieceShaderBuilder.cs) 提供可重复执行的迁移，并接入 `Apply`、`GameAssetBuilder.BuildP1`、`GamePolishBuilder.PolishReadability`，防止以后重新生成资源又回退。通过 Unity MCP 加载真实预制体、执行幂等装配并保存，确认 `Body` 是独立子节点且单位缩放，继续使用共享 `ArcanePiece` 材质；根节点保留 2 个组件、7 个子节点。预制体装配通过不等于运行动画通过，Play 记录见下文。

### 攻击文字与弹道改为公平的有界调度

保留数量预算与过期清理；新增纯 C# 的 `FairFeedbackBuffer<T>` 存储值快照，按攻击来源和上次获准显示的时间分配机会：

1. `Offer` 接收请求。同来源达到自己的待播上限后，更新它最新的一份候选，不再追加；容量满时根据来源的上次显示时间选择替换，避免固定遍历顺序占满队列。没显示过的来源优先，同分按编号稳定选择，不随机丢弃。
2. `TryPeek` 查找当前可显示的来源，只查看、不消耗；暂时处于同棋冷却的请求可以被跳过，不拖住所有其他棋子。
3. 确实预约到文字或弹道名额后，才调用 `MarkDisplayed` 消费该请求并记下显示历史。满屏时暂时等待，不把整队请求出队丢弃。
4. 超过 0.5 秒的旧请求过期，不在战况变化后补播陈旧齐射。切回合 `Clear` 同时清候选与历史。

| 反馈 | 保留的上限与节奏 | 新的公平性保护 |
|---|---|---|
| 攻击口号 | 待播来源 12；同屏最多 7，计入总字数 20；间隔 0.12 秒；同棋冷却 0.65 秒 | 每来源只留最新一条；预约成功才消耗；满额候选按显示历史分配 |
| 弹道 | 待播 24；同屏最多 14；间隔 0.025 秒；每画面帧最多发 2 条 | 每棋最多待播 4 条，防止多连击独占；按来源公平取出 |

本轮增加 `BattleHitInfo.SourceId`：它是攻击者在本局的唯一编号。坐标会因换位改变，不能当作稳定身份；环境伤害或旧测试没有来源编号时使用 0。命中快照只保存数值、编号和坐标，不保存会死亡、回池的棋子视图引用。

这些都是**表现预算**，不是每次攻击能否造成伤害的条件。伤害始终在模型中结算。

### 继续按 Revolution 管理生命周期

- 反馈对象仍由 `RevPool` 借出与归还，不另建对象池。
- 事件仍走 `RevEvent`，身体动作复用已有 `RevMono` 驱动。
- 回合切换使旧异步代次失效，再清队列、预算和池对象；迟到结果只能归池，不能占新回合名额。
- 不修改 `Assets/Revolution` 框架快照，不增加逐棋子独立材质，不把表现预算改成无限。

## 6. 如何复现与回归

1. 从 `StartScene` 以编辑器直读资源模式进入战斗，先放置远程与近战棋子，再补放数颗一级棋子。
2. 用密集攻击场景同时观察：真实 `PieceAttacked` 事件、敌人血量、出手身体动作、待播文字与弹道。只看有没有一句口号不足以判定真实攻击。
3. 将每种星级的近战放在非相邻且隔着友军的位置，确认仍保持原位援击；旁边有敌人时优先打接触目标。远程始终全盘索敌。
4. 造出我方零气、敌方零气两种场景：我方保留围困状态和原有受击代价但能真实反击；敌方仍禁止出手。长按范围提示、目标列表、攻击事件与实际掉血应一致。
5. 压满表现预算，观察队列有界且不会长期固定偏向同一批棋子；请求过期后不补播陈旧齐射。
6. 攻击途中切回合、触发死亡、回池再借出，检查缩放、旧请求、旧回调与表现预约都已清干净。

### 未覆盖范围与已知限制

追加执行 `GameReadabilityChecks.Begin` 全场压力回归时，Unity 发生脚本域重载，`LastResult` 被重置为“未运行”，因此这次压力回归**不能计入通过**。重载销毁选关面板时，Console 还记录了既有 `LevelSelectPanel.OnRelease` 的 `NullReferenceException`（`LevelSelectPanel.cs:67`，frame 0）。该文件不在本轮修改范围，异常尚未修复；本轮不声称 Console 零异常。上述中断不替代或撤销此前已完成并单独核对结果的 169 场景/3758 断言、685 条业务断言与池化动画验收。

尝试终端编译 Unity 生成的 `.csproj` 时，已有 Rider 编辑器包出现 `PathLocator` 缺失，结果为 8 个错误、112 个警告。这条构建没有通过；不能将 Unity 编辑器重编译成功或离线回归通过，表述成“全部工程构建通过”。本轮不为这个战斗修复修改用户的依赖包配置。

本轮不打包 AB。编辑器直读通过也不能证明首次 AB 加载或手机性能已经通过。身体动作增加的是对现有棋子 Transform 的短时更新；实际 CPU、GPU、GC 和手机帧率仍需按[战斗性能优化规则](../战斗性能优化规则/战斗性能优化规则.md)测量，不能仅因使用对象池便宣称零开销。

未重建的旧 AB 可能仍是身体渲染器位于根节点的结构。代码遇到这种旧结构会跳过身体压缩，避免缩放整颗棋子；真实攻击与公平反馈照常。要在 AB 模式验收新的身体姿态，后续需先按项目资源工具重新构建对应预制体包，本轮没有执行。

## 8. 框架可行性结论与后续约束

本次改动位于业务规则与表现调度，现有 `RevEvent + RevMono + RevPool` 足以承载，不需要改框架内核。模型规则、只读目标查询和表现快照继续分开；运行稳定性以本轮实际回归结果为准。

今后保留三条检查：**规则攻击是否发生、基础出手动作是否可见、限量反馈是否公平**。数量上限解决“太多”，公平调度解决“总轮不到某颗棋子”，两者都要有。按用户最终选择，所有存活我方原地参战；后续改动不能重新加回玩家近战超距停攻或零气禁攻，也不能因自动移动拆掉一眼、两眼阵型。
