# 2026-10-19：进入游戏时报“UI图集像素未绑定”

**一句话总结：** 图集文件没有丢，按钮引用的图片也没有配错；问题是负责监听 Unity 图集请求的服务被**注册了，却还没有被创建**。Unity 第一次要图集时无人接听，随后虽然把图集加载到了内存，也没能把它交回给最初等待图片的 Unity 渲染链路。

## 1. 玩家看到了什么

从 `StartScene` 进入游戏时，过场停住，控制台出现：

```text
InvalidOperationException: UI图集像素未绑定：btnPlay / UI_Begin_btnAdventure
```

这里的 `btnPlay` 是首页按钮，`UI_Begin_btnAdventure` 是它使用的 Sprite（图片资源）。异常在 [`GamePresentation.WaitUntilReadyAsync`](../../UnityProject/RevGame.Unity/Assets/GameScripts/View/Scene/GamePresentation.cs) 的画面就绪检查中抛出：如果 `Image` 有 Sprite，但 `sprite.texture` 为空，或 `mainTexture` 仍是白色占位纹理，就不允许撤掉过场遮挡。这是一道**发现坏画面的门禁**，不是制造坏画面的代码；删掉检查只会把白按钮直接展示给玩家。

## 2. 先分清三个容易混淆的东西

1. **Sprite（图片的引用）**：预制体里的按钮可以知道“我要用 `UI_Begin_btnAdventure`”，但此时不代表能读到它的像素。
2. **SpriteAtlas（图集）**：Unity 把多张 Sprite 的实际像素打在同一张纹理里；本例的按钮图片属于 `UIMenus` 图集。
3. **图集请求回调**：Unity 找不到 Sprite 的像素时，会发出 `SpriteAtlasManager.atlasRequested`。项目的 [`GameSpriteAtlasService`](../../UnityProject/RevGame.Unity/Assets/GameScripts/View/Resources/GameSpriteAtlasService.cs) 收到请求后，通过 `RevResManager.LoadAsync` 加载对应图集，再调用 Unity 提供的 `register` 回调，把图集交给 Unity。

**“预制体里有 Sprite”“图集服务已加载 SpriteAtlas”“按钮已经绑定像素”是三种不同的状态。** 只验证前两种，不能保证最后一种。

## 3. 为什么会发生：注册服务，不等于创建服务

[`RevServices.Register<TService, TImpl>`](../../UnityProject/RevGame.Unity/Assets/Revolution/Runtime/RevServiceLocator/Facade/RevServices.cs) 是**懒创建**的：调用 `Register` 只登记“将来需要时创建什么”，第一次 `GetRequired<TService>()` 才会真正运行构造函数。

而图集请求监听恰好写在 `GameSpriteAtlasService` **构造函数**中。修复前启动时序大致是：

```text
GameBootstrap.Awake
  └─ Register<GameSpriteAtlasService, GameSpriteAtlasService>()
     （只登记；构造函数还没运行，atlasRequested 还没人监听）

Unity 为场景或 UI 里的 Sprite 寻找图集
  └─ 发出 atlasRequested → 此刻没有项目监听者

GameFlow 稍后进入异步预热
  └─ GetRequired<GameSpriteAtlasService>()
     └─ 这时才创建服务、订阅事件，并加载 UIMenus 等图集

首页按钮接受检查
  └─ Sprite 引用还在，但 Sprite 像素仍未绑定 → 抛出异常
```

本次失败现场同时观察到：

- Unity 提示 `SpriteAtlasManager.atlasRequested wasn't listened to while ... requested`，说明确实出现过无人监听的请求。
- `UIMenus` 资产存在，包含 `UI_Begin_btnAdventure`；其图集和图片的 AB 归属均为 `atlas_uimenus`，不是图集漏打包。
- 图集服务的条目后来已经显示 `Atlas` 不为空、加载完成，但 `btnPlay` 的 `sprite.packed` 仍为 `false`，`sprite.texture` 和 `Image.mainTexture` 都是空的。
- 事后强制 `Image.SetAllDirty()`、`Canvas.ForceUpdateCanvases()` 并渲染相机，失败现场仍未恢复绑定。所以**“加载完再刷新 UI”不是本例可靠的修复方法**。

这些证据共同指向**订阅事件的时机太晚**，而不是 Shader、Excel 配置、按钮 GUID 或 `ResMap` 有误。不能把“图集已经加载”误判为“Unity 已收到这张图集的注册回调”。

## 4. 怎样修复

在 [`GameBootstrap.Awake`](../../UnityProject/RevGame.Unity/Assets/GameScripts/Bootstrap/Startup/GameBootstrap.cs) 里，先调用一次 `RevInitialize.Initialize()`，再注册图集服务，紧接着**立刻取用一次**：

```csharp
RevServices.Register<View.GameSpriteAtlasService, View.GameSpriteAtlasService>(owner: this);
RevServices.GetRequired<View.GameSpriteAtlasService>();
```

第二行不是为了保存服务字段，而是强制服务当场创建，让构造函数立即订阅 `SpriteAtlasManager.atlasRequested`。它必须发生在启动异步加载、打开面板、展示依赖图集的 Sprite **之前**，不能等到 `GameFlow` 预热时再第一次取服务。

这样之后的调用链变成：

```text
框架初始化 → 登记图集服务 → 当场创建并订阅 Unity 图集请求
                                    ↓
Unity 要图集 → 服务收到请求 → RevResManager 加载 → register(图集)
                                    ↓
                         Image 拿到实际纹理 → 就绪检查通过
```

所有权仍交给 `RevServices`：`GameBootstrap` 注册时传入 `owner: this`，销毁时执行 `UnregisterAllOf(this)`；服务 `Dispose()` 负责取消 `atlasRequested` 订阅并释放它持有的图集资源。不另建全局单例、不保留过期引用，也不需要修改 RevGame 内的 `Assets/Revolution` 框架快照或预制体。

**框架后续改进（2026-10-19）：** Revolution 的 `main` 在类型注册重载新增了可选参数 `eager: true`，以后同步到 RevGame 的 package 快照后可写成 `RevServices.Register<View.GameSpriteAtlasService, View.GameSpriteAtlasService>(owner: this, eager: true)`。它会在 `Register` 返回前完成构造与订阅；默认仍懒创建。**本次 RevGame 快照尚未同步新 API，所以当前经过 Play 验证的代码保留上面两行，不要提前改成 `eager` 导致编译失败。**

> **不要采用的“修复”：** 删除就绪检查、反复强制刷新 Canvas、每帧扫描并替换 Sprite、绕过 `RevResManager` 从磁盘直读图集。这些做法没有解决首次回调丢失，还可能破坏 AB/热更、引用计数或生命周期。

## 5. 怎么证明这次确实修好了

在 Unity 编辑器 **直读资源模式**下，清掉旧 Console 记录后，从 `StartScene` 冷启动并走了真实操作：

1. 首页 `btnPlay` 对应的 `UI_Begin_btnAdventure`：`packed=True`，`sprite.texture`、`Image.mainTexture` 都是 `UIMenus` 的实际纹理。
2. 点真正的首页按钮进入选关，再点第 1 章进入战斗：流程到达 `Battle`，`IsTransitioning=False`，`LastError` 为空；21 个带 Sprite 的活动 `Image`，未绑定数量为 **0**。
3. 返回首页：流程到达 `Home`，`IsTransitioning=False`，`LastError` 为空；2 个带 Sprite 的活动 `Image`，未绑定数量为 **0**。
4. 这一轮未再出现“UI图集像素未绑定”；相关 C# 文件无诊断，`git diff --check` 通过。测试结束后已退出 Play。

**验证边界：** 本次没有执行编辑器 AB 模式、Android 真机或整套场景自动回归；直读模式通过不能冒充 AB/真机通过。首次切战斗的更早一次试验曾遇到 Play 中途域重载，后续用全新冷启动完整重测通过；不要把那次中断当成正式战斗验证结果。

## 6. 下次怎样避免再踩坑

### 编码时的启动检查

- 凡是在**构造函数**中订阅 `SpriteAtlasManager.atlasRequested`、Unity 事件、消息总线或建立其他“必须从第一帧开始监听”的服务，都要确认它在第一次事件之前真的**已经实例化**。不要只看到 `Register` 就以为监听已生效。
- 当前游戏框架快照继续使用“`Register` 后立刻 `GetRequired`”；等更新框架 package 快照后也可在类型注册上用 `eager: true`。两者都保持服务由容器创建和注销。不要把 `GameSpriteAtlasService` 改成永久静态监听：反复 Play 会累积订阅和资源租约。
- 打开 UI 前继续使用 [`GameSpriteAtlasService.PreloadAsync`](../../UnityProject/RevGame.Unity/Assets/GameScripts/View/Resources/GameSpriteAtlasService.cs) 的图集屏障；**预载能保证资源到齐，但不能代替尽早订阅请求**。两条保障要同时有。
- 保留 [`GamePresentation.WaitUntilReadyAsync`](../../UnityProject/RevGame.Unity/Assets/GameScripts/View/Scene/GamePresentation.cs) 的纹理门禁：如果 Sprite 引用存在但纹理仍空，就要报告具体控件和图片名称，而不是放行白图。

### 测试时的最短回归路径

1. **冷启动** `StartScene`，不要先运行“加载所有图集”的测试：预热缓存会掩盖首次订阅时序错误。
2. 看首页 `btnPlay` 是否有纹理，然后点击“开始”→选关→第 1 章→战斗→返回首页；每一屏在过场撤掉前检查 `Image` 是否真有像素。
3. 停止 Play 再来一次，检查图集事件是否正常重订阅、旧租约是否释放。
4. 准备发布时，另在**编辑器 AB 模式**和目标真机重复流程，并检查 `ResMap`、图集包、Shader、图集依赖；本次尚未执行这两项，不能省略。

### 再看到类似错误时先看哪里

- `atlasRequested wasn't listened to`：先看 **监听服务何时创建**，不要先改图片文件。
- `GameSpriteAtlasService` 的图集条目已加载，但 `sprite.texture` 仍空：查 **Unity 的注册回调是否在首次请求时被保存并执行**，不是只查 `RevResManager` 是否加载成功。
- `图集加载失败：名称，ErrorReason`：这是另一类问题，应按 `handle.ErrorReason` 检查逻辑路径、AB 映射和资源文件，不能把所有白图都归因于懒创建。

**记住这条经验：需要“抢在事件发生前监听”的服务，先确认对象已经创建；注册表里有名字，不代表事件已经有人在听。**
