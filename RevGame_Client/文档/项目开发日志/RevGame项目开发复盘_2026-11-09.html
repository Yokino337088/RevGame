HISTORY / 01

为什么做这个项目

README 中，作者交代了立项背景。Revolution 来自实习中的技术积累，希望以独立游戏开发者的视角，把门面、编辑器工具和跨平台流程放进一套真实业务里验证。项目也承担带教任务，由伙伴分别实践美术与策划工作流。

提交呈现出来的开发心路有三个连续问题。最早是这一局能不能完整玩完，后来是复杂业务进来后，状态和资源能不能维持正确，再后来是每次修复能不能复现、验收，并反馈到框架。这是对开发决策的回顾，个人感受以作者已有记录为准。

证据口径为主线 2964e5f7 到 c303f004 的全部 172 条提交。阶段按提交先后划分，11 月 7 日分为联机迭代与原生决斗两段。历史报告对应当时的构建、环境与样本。

PRACTICE / 09

现在怎样在 RevGame 里开发

StartScene 的 GameBootstrap 装配服务并初始化框架一次。GameFlow 通过 FSM 与 RevScope 管业务域，通过 RevScene 完成场景交割。UI 交互经过真实 Logic 或 Service，Model 保存规则事实，View 消费回执。先找状态所有者，再选文件和验证入口。

Bootstrap→GameFlow / 域→Logic / Service→模型与配置→UI / View
六章远征 · GameScene

BattleLogic 管阶段，IBattleService 和 BoardModel 提交规则，Boss、帮手与敌人按职责分目录。伤害提交先于视觉反馈。

独立无尽 · EndlessScene

EndlessLogic 管节拍，EndlessService 持有本局规则、状态和存档。盘内棋子可复用，外围敌潮和成长沿无尽契约。

九路围棋 · PvpScene

GoCore 管棋规，PvpService 管对局提交和状态。LAN 与 Fantasy KCP 是不同传输。DeepSeek 提供建议和候选动作，经统一规则入口校验。

原生决斗 · PvpDuelScene

C# 宿主通过 DuelCorePipe 向 C++ 交付完整连续帧。原生核心推进确定性模拟，显示使用快照，验收看双端帧号和指纹。

资产和自动化怎么选

  • 改资源。 配置从 Excel 进入导表与校验，运行期用逻辑路径和 RevResManager。Sprite 图集、共享 Shader 和各模式 AB 按实际使用范围划分，冷启和重入时检查引用。
  • 做 Unity 操作。 单次编辑通过实时发现的 RevCLI 动作。固定对象树适合入库 JSON。跨资产计算与项目门禁由 Editor 配方承担。可跨项目复用的缺口回 Revolution 源仓库修复并导出。
  • 验真实流程。 用 RevMCP 发现运行态能力，调用玩家共用入口，等 accepted 之后的实际完成，断言与 finally 同时写入。线下规则、Editor 真 AB、独立 Player、真实服务和真机分开记录。
  • 给后来者留入口。 项目代码的每个类、字段、方法和重要实现段都用中文说明用途、单位、所有者、失败路径、顺序和原因。

LESSONS / 10

踩过的坑怎样改变了验收

问题追到哪一层留下的门禁
UI 冷启动白图引用存在，Unity 的像素绑定未完成。懒装配漏过首次 atlasRequested。Bootstrap 提早装配监听。真 AB 验首开和重入，验证引用归还。
特效白剪影与低星反馈缺失采样参数和真实攻击路径要分开查。MPB 可能覆盖 _MainTex，低星攻击可能没走统一反馈。比较 Shader 采样、触发回执、池代次和可见结果。保护结算与表现分工。
切章后读到旧背景领奖事件同一帧启动剧情和换背景，旧章就绪可能被沿用。从真实领奖入口检查加载顺序，断言实际章节、可画状态和流程完成。
网络握手、停滞与非法 Agent 落点固定字节区分收包与解码。HTTP 成功只覆盖请求，合法动作和终局要在棋局层验证。实跑对应传输、后台、重连与双端终局。对照棋谱、序号和指纹，真实凭据留本机。
切 Android 后 Editor 粉屏旧分支把 Build Target 当成运行宿主。拉取前后加载器相同，共享 Shader 包变化。何时切换本机偏好缺少历史证据。分开核对图形 API、包来源和实际画面。保持触发条件，只改选包后做冷 AB 前后对照。

由这些记录能确认，Revolution 的流程、资源、UI、池、导表和自动化能力已在多种真实玩法接线上使用。项目特有的分包、协议、规则和断言由 RevGame 维护。每份验收只覆盖当次平台、输入和运行时，尤其要把 Editor 直读、桌面真 AB、Android 与跨设备网络分开。
