# 战斗攻击与表现公平性回归

## 2026-10-31 攻击差异化更新

普通我方已由全盘援击改为棋种有限射程。当前默认用例同步验证射程内攻击、射程外拒绝、重弩直线限制和显示射界一致性；40来源公平性夹具改用同一射程内的40名弓箭手，避免把“打不到目标”误判为表现调度遗漏。下方2026-10-19的全盘援击说明保留为历史背景，不是当前规则。

新增专项入口：

```powershell
dotnet run --project RevGame_Client/Tests/CombatAttackRegression/CombatAttackRegression.csproj -c Release -- RevGame_Client/UnityProject/RevGame.Unity/Assets/GameRes/Data piece-patterns
```

专项直接调用生产攻击几何和伤害服务，覆盖九种棋子的目标上限、实际扣血、伤害快照、范围外不受伤、缓冲清理、大棋去重、3×3完整爆区、重弩不拐弯、牧师治疗不复活、刺客残血选敌和无副作用预判。当前96条断言。`enemy-ranged`模式继续检查已有远程1.5倍强化，不能被新配方覆盖。

当前全量默认入口仍失败于任务开始前就存在的“首手时刻到期真实提交一手”增援断言；这项没有删除或放宽。不能以专项通过冒充默认全套通过。逐棋种实际AB画面由 `GamePieceAttackVisualChecks` 和真实RevMCP/GM验证，详见[开发说明](../../文档/数值平衡/棋子行为差异化_2026-10-31.md)与[HTML验收报告](../../文档/游戏玩法修改/九种棋子差异化功能验收_2026-10-31.html)。

这是放在 Unity 工程外的**可执行断言程序**。它直接链接当前工作区的真实战斗服务、棋盘/气眼/攻击规则、棋子目录、配置生成类、Revolution 配置解析器与事件门面，不复制攻击算法，也不使用预期值替代伤害结算。

从仓库根执行（需要 .NET 10 SDK）：

```powershell
dotnet run --project RevGame_Client/Tests/CombatAttackRegression/CombatAttackRegression.csproj -c Release
```

程序自动查找 `Assets/GameRes/Data`，由已有 `GameConfigFileLoader` 读取全部 11 张真实导表数据，经框架 `RevDataTable`/`RevDataTextFormat`/`RevDataFieldParser` 和 `GameConfig.Initialize` 完成解析与校验。也可以把数据目录的绝对路径作为程序第一个参数。

## 覆盖范围

- 9 种棋子 × 1/2/3 星 × 6 种规则场景，共 162 个场景：正常攻击、非相邻且隔友军仍援击、我方零气反击后解围恢复、敌方零气仍禁攻、一眼守阵仍能攻击、两眼活棋仍能攻击。
- 玩家近战的基础场景使用身体边缘相邻敌人；额外援击场景让全部 9 种棋子面对友军遮挡和非直线跨盘目标，核对目标查询、显示射界、真实攻击、掉血与保持原位。3 星新落棋按真实 StarConfig 使用 2×2 身体，围困夹具也按完整身体边界布置。
- 经过真实 `StepSide → MoveRules → Attack → DamagePiece`；同时断言攻击事件、带正确攻击者编号的伤害事件和敌人实际掉血，不能仅凭“目标列表非空”声称出手成功。
- 增加 2 个同场/连射场景：前十颗三星、后三十颗一级远程按真实名单顺序在同一步攻击，逐一验证 40 个攻击者编号均派发攻击并造成伤害，伤害快照总和等于目标扣血；连射首发杀敌后，剩余额度重查并攻击第二名敌人。由此区别“规则没有出手”与“表现预算漏画”。
- 增加 5 个定向边界场景：单格剑士/两格刺客均优先相邻目标，死亡棋子不出手，没有敌人不虚构攻击，被围玩家仍保留真实受击增伤。全部零气玩家造局还会核对出手后零气状态没有被错误清除。
- 直接链接真实 `FairFeedbackBuffer`，模拟 40 个来源以始终相同顺序持续齐射，分别核对 12/24 容量上限及全部来源都能轮到显示。另查同源合并、单源连射上限、无编号旧事件兼容、预算暂停保留候选、超时丢弃、同源冷却不阻塞他人、退出清空候选与历史。
- 对照输入为 20 来源按固定编号顺序每 0.625 秒齐射、每 0.12 秒最多显示一份、候选寿命 0.5 秒，持续 10 秒，两侧容量都为 12。旧式 FIFO 摘要模拟只有 **5/20** 个来源显示过；同输入下真实新 `FairFeedbackBuffer` 为 **20/20**。旧侧只摘录“队满拒收后来者”和 FIFO/过期规则，**不是完整旧 BoardView 的复刻或旧游戏 Play 实测**；它证明固定入队顺序可造成饥饿，不证明旧界面每局恰好只显示五颗棋子。新侧直接链接真实修复类。

`BattleAttackFixture.cs` 只负责造局、调用真实私有服务方法；它在 Assets 外，不会编入游戏。`OfflineHost.cs` 只补没有启动 Unity/资源系统时的最小编译接口：坐标类型、日志出口、空默认域及明确禁止运行的数据表缓存入口。配置解析、攻击、气眼、事件派发和公平排序均未使用桩算法。

## 如何判断结果

成功打印场景数和断言数并返回退出码 0；任何断言失败都会打印中文原因、调用栈并返回 1。应运行 `dotnet run`，不能把没有测试适配器的 `dotnet test` 所显示的“0 项测试”当成通过。

2026-10-19 本机实测：169 个规则场景（162 个棋种/星级边界场景 + 2 个同场/连射场景 + 5 个定向边界场景）、3758 条断言通过，其中公平缓冲及旧式入队摘要对照为 2794 条。大量断言是固定输入多帧的容量不变量，**不是 3758 个独立玩法场景**。既有字段 `_decisiveSupportUsed` 未读取会产生 CS0414 警告。

本程序证明纯 C# 规则和候选调度行为；不覆盖 Unity Play 生命周期、真实池化弹道/飘字的最终画面、GPU 性能、AB 资源加载或手机帧率，也不能代替实际游玩验收。用户最新要求全部我方棋子参战，因此近战没有贴脸敌人时改为原位援击，零气时也不会整颗停攻；敌人的原射程和零气禁攻继续保留。气眼对我方仍影响受击代价，不在测试里另造出手削弱倍率。
