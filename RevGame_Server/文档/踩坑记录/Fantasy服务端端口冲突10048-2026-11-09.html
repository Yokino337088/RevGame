FIELD NOTE / 01

故障现场

双击 start-server.cmd 后，Fantasy 在创建 Scene 的监听套接字时抛出 Windows 错误 10048。这表示要绑定的协议、地址和端口已被占用。

本机证据查到的状态
2026-11-06 启动的旧 Main，PID 108116监听 127.0.0.1:11002/TCP 与 0.0.0.0:20000/TCP
旧 bin 下的 Fantasy.configGate 的外网协议仍为 TCP，配置里只有一个 Scene
当前源码的 Fantasy.configGate 外网使用 KCP/UDP 20000，Gate 与四个 GoBattle 分别占用内网 TCP 11002–11006

旧脚本只检查产物是否存在，因此换机器或更新源码后，仍可能启动旧 DLL 和旧配置。当前版本即使使用了 KCP，对局服务内部仍要绑定 TCP 11002，因此残留进程也会挡住新版本启动。

FIELD NOTE / 02

现在怎么启动

先安装 .NET 8 SDK。打开 RevGame.Server 目录，双击 start-server.cmd，或在终端运行 .\start-server.ps1。看到 Process:1 Startup Complete SceneCount:5 后，本机客户端可连接 127.0.0.1:20000。

确实需要保留原实例时，可以给新实例指定空闲端口。内网从 12002 起连续分配五个端口，外网改为 UDP 21000。

.\start-server.cmd -InnerBasePort 12002 -OuterPort 21000

只撞内网时只需 -InnerBasePort。修改外网端口后，客户端和防火墙也要使用新的 UDP 端口。其它设备填写服务端机器的实际 IPv4。同机测试的内网 TCP 监听仍在回环地址上。

FIELD NOTE / 03

修复落点

  1. CMD 把参数和退出码交给同一份 PowerShell 启动器。启动器从脚本目录定位工程，从任意当前目录调用都能找到配置。
  2. 有 SDK 时从当前源码构建到独立运行目录，避免使用旧产物或覆盖运行中的 DLL。只有运行时时，使用完整的预编译产物；源码配置和产物配置不一致会明确报错。
  3. 从 Fantasy XML 读出每个 Scene 的地址和协议，逐一试绑定。失败会显示 Scene、TCP/UDP、地址、端口和可查到的进程 PID。
  4. 端口覆盖只写入本次启动目录里的 Fantasy.config，Fantasy 从程序旁加载它。预检后仍可能发生抢占，正式绑定失败会保留非零退出码。

开发配置的发布地址使用回环 IP，跨设备连接由客户端填写实际服务端 IP。正式绑定和 Scene 生命周期仍由 Fantasy 负责，启动器负责构建、配置和端口诊断。Revolution 客户端链路未参与本次服务端验证。

FIELD NOTE / 05

下次排查顺序

先按报错的协议检查本机监听进程，再核对实际运行的配置。KCP 使用 UDP，内网默认使用 TCP，两种协议要分别查询。

Get-NetTCPConnection -State Listen -LocalPort (11002..11006)
Get-NetUDPEndpoint -LocalPort 20000
Get-Process -Id <OwningProcess>

确认进程归属后从原窗口正常退出，或给新实例指定其它端口。源码机器使用 .NET 8 SDK 和可访问的 NuGet 源或缓存。运行预编译产物需要 .NET 8 ASP.NET Core Runtime 和完整的运行目录。
