九路围棋服务器与协议

本目录提供 Fantasy 2026.1.2003、.NET 8 的单进程休闲围棋中转服务器。单 Gate Scene 拥有大厅、匿名玩家 Entity 与房间 Entity；状态只存内存，不依赖数据库或 Control Center。服务器负责匹配、身份绑定、序列去重、操作转发、断线感知与恢复窗口。棋规只由客户端共享的 GoCore 计算，不宣传服务端反作弊或官方排位。

本机开发

在本目录运行 ./start-server.ps1。同机 Unity 连接 127.0.0.1:20000；同一局域网另一台设备填写开发机当前 IPv4 与端口 20000。地址由 PvP 界面输入，不写死某台电脑的 IP。

Server/Entity/Fantasy.config 外网监听 0.0.0.0:20000/TCP，内部 127.0.0.1:11002/TCP。实际启动日志应出现“九路围棋中转大厅已就绪”。云端部署仍使用这一个进程，开放外网 TCP 20000 即可；停服或租期结束后客户端显示连接失败/断线提示，远征、无尽和局域网模式没有服务端启动依赖。

修改 .proto 后运行 ./export-protocol.ps1，再执行 dotnet build Server/Main/Main.csproj。Unity 侧 Assets/csc.rsp 的 FANTASY_UNITY 使业务程序集生成消息注册；当前安装版本的客户端 Handler 基类是 Message&lt;T&gt;，不是旧技能示例的双泛型签名。不要手写注册表或改 .g.cs。

一次对局的消息顺序

1. C2G_GoHelloRequest 携带 revgo-1、昵称、同源规则 JSON、入门/进阶场次，返回匿名恢复令牌。

2. C2G_GoMatchRequest 加入/取消队列；只匹配完全相同规则与场次的玩家，随机分配黑白。

3. G2C_GoState 推送房间和完整操作序列。每条操作有全局连续 Sequence、真实身份 Side、Kind、坐标、思考毫秒数与前后 StateHash。

4. C2G_GoCommandRequest 经身份/包长/序号/回合/速率门禁后转给双方。完全相同的重发幂等，不同内容的旧序号拒绝。接收客户端必须重放 GoCore 并比对哈希后才能落屏。

5. C2G_GoSyncRequest 或携带原 Token 的新 Hello 恢复完整序列。连接失效时队列立即移除，对局保留配置中的重连窗口。

6. C2G_GoLeaveRequest 通知对手房间关闭，自己回大厅；双方退出或保留期满后销毁房间。断线期间的本机 Token 仅用于同一次服务进程，服务器重启后旧 Token 过期。

Kind 固定为：1 落子、2 停一手、3 认输、4 切换整组死子、5 确认数子、6 继续对弈、7 超时、8 断线。标记死子与确认不按落子轮次限制；最终是否合法由 GoCore 校验。Phase 为 idle、queued、playing、disconnected、closed。

规则 JSON 来自项目 Excel 导表；服务端读取其中 reconnectWindowSeconds 与 matchTimeoutSeconds 管理连接寿命，默认分别为 90/60 秒，并限定在 1–600 秒范围内。其它围棋配置只用于双方一致性握手。每房最多 1024 条操作、每连接每秒最多 20 条已认证请求、最多 1024 个匿名身份，这是防止无限内存/广播的服务边界，不是围棋玩法参数。

可复现验证

Tools/GoRelayProbe 是真实 TCP 客户端工具，编译同一份客户端 GoCore 与服务端导出协议，工具直接处理外网包头，不替代生产 Fantasy 客户端。

dotnet run --project Tools/GoRelayProbe/GoRelayProbe.csproj -- 127.0.0.1 20000 smoke
dotnet run --project Tools/GoRelayProbe/GoRelayProbe.csproj -- 127.0.0.1 20000 expiry
dotnet run --project Tools/GoRelayProbe/GoRelayProbe.csproj -- 127.0.0.1 20000 opponent <规则JSON文件>

smoke 验证两客户端匹配、取消、身份拒绝、去重、共同回放、恢复和退出；expiry 真实等待默认 60/90 秒校验队列与断线窗口；opponent 与 Unity 真客户端匹配，轮到自己时停一手、数子阶段确认，最多运行五分钟。测试输出令牌仅保存在内存，不打印令牌。原始证据放仓库 .codex/work/，不提交构建产物。

客户端网络桥只在进入服务器对战后连接。连接与 RPC 有 6 秒兜底，业务心跳每 2 秒一次；旧回调靠 generation 失效。发生故障先释放自己的 Fantasy Scene/Session，再报告可读原因，不关闭 Revolution 域或清理单机资源。网络桥自己的 Poll() 需要由 PvP 服务持续驱动。
