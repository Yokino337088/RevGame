分段定位

两进程用同机单调时钟，按房间与操作序号逐条关联。各段 P99 分别排序。最慢 1% 的均值则对每轮总耗时最高的 170 条请求按段拆解。

Battle 段包含合批等待、跨 Scene 调度、棋规校验和 Gate 继续执行。回包入队后的时间包含 KCP 刷出、回环传输、探针排队及解包。这两段无法细分为纯棋规 CPU 或纯网络传输。普通落子日志在基线慢请求中平均约 0.02 ms。

最终版最慢 1% 的回程均值从 67.76 ms 降至 35.20 ms。跨 Scene 段的慢请求均值仍约 66 ms，首手 P99 高于全量基线首手。这解释了总 P99 的收益小于消息减量比例。

Gate 同一局只允许一手在途，每批按位置返回各房间的结果。对协商增量的客户端，服务端每手只回传一条新棋谱，回包和推送的棋谱条数各减少 94.3%。旧客户端及握手、重连、主动同步仍接收全量。客户端遇到断序时锁定操作并限频请求全量。

正确性与清理

  • 最终版 KCP 压测逐席核对棋谱序号与指纹链，1000 个座位均拼接到同一终局指纹。满载换 Socket 能恢复原房间和全量棋谱，所有座位离席后均为空闲。
  • 旧客户端 TCP 烟测通过，包括第二手收到全量棋谱、伪造首手被拒绝、幂等重发和重连。
  • 客户端离线增量与身份专项断言通过，覆盖缺口补齐、锁定与限频、重复命令和指纹篡改。
  • Unity 2022.3.15f1c1 实际 Play 以新客户端和旧协议探针对弈。先用 rev_discover 找到编辑器能力，再用 rev_call 刷新、编译及启动 Play。随后 rev_discover(game,pvp.) 找到实际业务入口。两段 rev_run 验证双停、双方数子、终局序号 4、掉线全量恢复和退局，最后用 rev_call(editor.stop) 退出 Play。

原始计时、探针和 Unity 证据在忽略目录 .codex/work/pvp-scale/。最终压测 Hotfix.dll SHA-256 为 020b655ba748a5b8c817a8c53a44adbf0295fb0dc599e66f32fe1860b32baee4。结论覆盖当前单机 Gate 与 Battle 组合和固定回环突发。公网抖动、多机和长时间负载的尾延迟尚未测量。
