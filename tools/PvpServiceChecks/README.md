# 围棋服务计时与状态回归

```powershell
dotnet run --project tools/PvpServiceChecks/PvpServiceChecks.csproj -c Release
```

本工程直接编译实际 `PvpService`、表现 partial 和 `GoCore/GoClock`。仅为未参与检查的 Unity JSON、Fantasy/UTP 连接与表加载提供最小编译边界；没有真实网络、Unity 场景或 AB 加载，不应把这个结果写成联机验收。

服务新增 `LeaveAsync` 后，本工程也直接链接框架真实 `RevTask.cs`（包括 MethodBuilder 与 Awaiter）。这里只替代依赖 Unity PlayerLoop 的调度器及日志出口；调度器入口会明确抛出“不支持”而不会假完成。本套断言不调用 `LeaveAsync`，其退出回执与跨帧清理必须由真实 Play 验收。

2026-11-06 实际运行 **14 条断言通过**，覆盖：

- 玩家在最后读秒结束后点击落子，会提交超时而不会先落下棋子。
- 没有点击时，`Poll` 也会提交自己的超时结果；时钟尚有余额不能伪造超时。
- 收到超时后的远端普通落子，规则、时钟、棋谱均不推进，且返回明确原因。
- 重复服务器状态与相同棋谱的重连不会赠送新的思考时间。
- 旧推送不会提前解开尚未回执的提交锁；业务拒绝仅释放等待锁，不错误标成服务器断线。
- 邀请与邀请回复返回真实拒绝结果，不因函数调用完成就判定成功。

测试中把“本手开始时间”前移来复现临界时刻，实际超时判断仍由真实 `Submit/Poll` 执行，不直接伪造终局字段。传输可靠性、断线重连窗口与双客户端一致性需要另外执行真实网络测试。

2026-11-06续作：当前18条断言通过，新增双停进入计分、非法确认耗时拒绝且棋谱不变、零耗时远端确认及双方确认终局。本机真实网络终局/重连/停服结果另见项目进度同步目录的九路围棋联机闭环验收报告。
